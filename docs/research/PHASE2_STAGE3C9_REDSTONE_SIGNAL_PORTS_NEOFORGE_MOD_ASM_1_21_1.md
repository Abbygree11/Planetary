## 1/4 — mechanism and declaring-owner dispatch

| Owner | Author / consumer chain | Semantics |
| --- | --- | --- |
| `SignalGetter.getSignal(BlockPos,Direction)` | BlockState.getSignal; NeoForge shouldCheckWeakPower; if allowed, max with getDirectSignalTo | Two separate queried-side meanings: **signal output port** and **physical physical conductor weak check**, mod-overridable |
| `SignalGetter.getDirectSignal/getDirectSignalTo/getBestNeighborSignal/hasNeighborSignal` | Physical six-neighbor sampling, early return at 15, direction parameter as API query side | Default PHYSICAL when caller/mod external, do not flip it globally at seams |
| `BlockBehaviour.BlockStateBase.getSignal/getDirectSignal/isSignalSource` | Dynamic concrete Block implementation | **SHARED_SAFE virtual dispatch**, modded block properties and arbitrary capability semantics preserved |
| `RedStoneWireBlock.getConnectingSide` | Four tangent ports; NeoForge canRedstoneConnectTo(physical neighbor, nullable side), above/below continuation, sturdy-face/survival and `RedstoneSide.UP/SIDE/NONE` | OWN connection graph, distinct from general `SignalGetter` signal strength |
| `RedStoneWireBlock.calculateTargetStrength` | Temporarily changes instance-wide `shouldSignal`; reads best neighbor; queries wire and above/below strength; writes POWER and neighbor fan-out | Shared singleton mutable state requires reentry/recursion ordering preservation; a global added signal pass may cause oscillation or duplicate fan-out |
| `DiodeBlock` and `RepeaterBlock` | Physical front FACING input, lateral `getAlternateSignal`/locking, delayed TickPriority, output opposite; NeoForge onNeighborNotify before directed neighborChanged | Directed **front/back/side** ports; `getClockWise/getCounterClockWise` physical plane by default |
| `ComparatorBlock` + `ComparatorBlockEntity` | Analog output stored in BE; container and item-frame input; COMPARE/SUBTRACT; scheduled 2-tick output; NeoForge getWeakChanges/onNeighborChange | BE output strength != POWERED BlockState; Stage2.3C-6 BE store and weak updates prerequisite |
| `ObserverBlock` | Front-facing updateShape triggers delayed pulse; output opposite side; neighbor updates | updateShape notification is not ordinary redstone neighborChanged |
| `RedstoneTorchBlock` | Neighbor event → scheduled tick, support below, burnout toggle list 60 ticks; direct vs weak signal different sides | Time-driver Stage2.3C-5 and orientation support Phase2; do not transpose physical World Y by default |
| `PoweredRailBlock/DetectorRailBlock` | RailState physical slope + graph traversal (powered rail depth 8); detector entity sampling + comparator output | Distinct rail graph and entity Phase7, not a RedStoneWireBlock subclass |
| `HopperBlock/HopperBlockEntity` / mod machines | Signal gating ENABLED state and independent BE inventories/capabilities/ticker + physical transfer ports | Power signal owner and item/fluid logistics owner distinct |
| `DaylightDetectorBlock` | Periodic sky sample and environmental world-time, updates block state | Global environment ownership Phase8; not arbitrary local-UP semantics |

## 2/4 — lifecycle and alternate producers

1. Physical world writes and server Level.neighborChanged/updateNeighborsAt* drive shape update + power refresh. Stage2.3C-4 established actual `Level/ServerLevel.updateNeighborsAt*` invokes NeoForge EventHooks.onNeighborNotify; **existing Planet `@Inject(HEAD)` cancels original path for bound world** and may skip mod event subscribers. Independent DiodeBlock NeoForge onNeighborNotify is an additional cancellation boundary; do not double-deliver events or cancel without honoring event response.
2. Wire getConnectingSide returns local appearance CONNECTION values while physical queried Direction is not trivially chart-local FACING. On side/bottom faces and seams, there are source+target chart frames, wire support local-UP, four tangent side ports and potential step-UP/DOWN continuation; a vanilla single-physical `Direction` redirection cannot substitute for explicit graph traversal, especially when crossing an edge.
3. Wire `shouldSignal` is a mutable block-instance field, temporarily disabled while calculating external strength, so extra recursive queries/async updates require a deterministic reentry contract. Wire power changes issue notifications at multiple adjacent and diagonal points; global `Level.updateNeighborsAt` redirection must preserve original event fanout, recursion-limits, flags and exact modded canRedstoneConnectTo callback.
4. Repeater lock/tick scheduling and comparator analog BE output use **deferred ticks** and `willTickThisTick` (Stage2.3C-5), plus BE persistence (Stage2.3C-6). Dedicated Observer.updateShape path and tripwire endpoints (range up to 41 physical cells) bypass simplistic neighborhood sampling. Rails have a separate graph. Item BlockItem placement and blockstate component application, player use, commands, worldgen/structures, mod wrench, mod BE tick/receiver network are independent signal authors.
5. Modded analog direction/value may not be represented by vanilla BlockState POWER (Create AnalogLeverBlock stores value in BE); a bridge returning only vanilla POWER misses modded analog and true sided BE inventories or redstone control. Create RedstoneLinkBlockEntity wireless network is **not a neighbor traversal** at all: only endpoints enter the physical redstone graph, with frequency network handled by the mod.
6. Planet code review: current `LevelMixin` / `ServerLevelMixin` intercept `updateNeighborsAt`, `updateNeighborsAtExceptFromFacing`, `neighborChanged` and Level neighbor shape, and `PlanetVanillaNeighborUpdates` dispatches target canonical aliases by calling actual `level.neighborChanged`. `PlanetSidedQueryFrame` describes *legacy virtual atlas* compatibility and is documented as not the authority for dedicated physical Planet worlds. There are **no dedicated production SignalGetter/RedStoneWireBlock/DiodeBlock/ComparatorBlock ModSignal Mixins** in inspected `src/main/java`. This is not proof those signals fail in-game; actual signal querying may get routed through existing Level/BlockRuntime/neighbor path. Must test.
7. BE and capabilities are separate; comparator/Hopper and mod machine BE ticking/persistent state will not be correct just because RedstoneWire updates. Stage2.3C-6 potential virtual BE ticker/NeoForge onLoad/attachment persistence remains unresolved gameplay risk.

## 3/4 — deepest safe shared boundary

| Mechanism | Classification | Boundary |
| --- | --- | --- |
| Physical `Direction`, `BlockPos`, `SignalGetter` six-neighbor sampling, chunk/BE physical keys and `Level.neighborChanged` defaults | **PHYSICAL_DO_NOT_TOUCH** | Existing 1.21.1 mods and foreign/fake Levels expect these APIs to return physical signal power |
| Original NeoForge shouldCheckWeakPower, canRedstoneConnectTo, diode event, comparator onNeighborChange and mod `BlockStateBase.getSignal/getDirectSignal` delegation | **SHARED_SAFE** dispatch/observation | Must always invoke true mod-provided extension/BlockState at original target bytecode boundary, not hardcode vanilla block IDs |
| Planet-aware source/target signal query frame, local 4 tangents/UP support, directed ports, wire rise/fall and carried signal strength | **OPT_IN_ALGORITHM** | Typed `PlanetSignalQueryContext` may include source, target, physical query side, canonical chart owner, normal vs direct, author/power and seam traversal; explicit opt-in only when Planet-owned semantics |
| Comparator, rail, tripwire, hopper, modded automation and network/BE wireless signal algorithms | **MOD_INDEPENDENT** implementations via safe callbacks | No single vanilla `getSignal` mixin replaces their internal state machine/tick/network |
| Entity on detector rail, comparator GUI/BER, particles and client animation | **CLIENT/ENTITY** | Separate acceptance from server signal graph |

**Why not deeper:** global remapping of SignalGetter.getSignal or Direction/BlockPos would rewrite every modded physical control network, Create's external port semantics, inventories, off-Planet and foreign fake Levels. **Why not shallower:** fixing RedStoneWireBlock.getStateForPlacement or a few named block FACING props ignores NeoForge extension dispatch, DiodeBlock direct-signal port, comparator BE analog, signal-world separate recursion/update pipeline, Create wireless link and modded signal writers. Only future typed Planet semantic module plus thin 21.1.1/NeoForge adapters can retain both portability and arbitrary mod extension behavior. No production runtime changes.
