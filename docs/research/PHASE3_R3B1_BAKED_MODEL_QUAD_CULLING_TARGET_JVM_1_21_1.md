## 2/4 — Original execution-owner / shape-vs-model boundary

The original compiled selected invocation TSV proves:

- `ModelBlockRenderer` invokes `BakedModel.getQuads` **6 sites**; uses `BakedQuad.getDirection` **5 sites**; `Block.shouldRenderFace` **2 sites**. Distinct `tesselateWithAO` and `tesselateWithoutAO` methods are reached from the renderer, with vanilla `getLightColor`, `BlockColors.getColor` and `BlockAndTintGetter.getShade` in this original name-filtered graph.
- `Block.shouldRenderFace` invokes `BlockState.getFaceOcclusionShape` **twice**, as well as `BlockState.skipRendering`, `hidesNeighborFace` and `supportsExternalFaceHiding`; preserve exact NeoForge and overridable dispatch rather than globally replacing culling semantics.
- `SectionCompiler.compile` invokes `RenderChunkRegion.getModelData`, `BakedModel.getModelData` and `getRenderTypes` and `BlockRenderDispatcher.renderBatched`. Rendering quads/model-data is a different owner from the `BlockState` that Phase2 writes. Two earlier original `3R-2k/2l` tests establish source-region/ModelData snapshot ownership.
- `BlockRenderDispatcher` invokes `ModelBlockRenderer.tesselateBlock` twice among selected method bodies and has its own `BakedModel.getModelData` and `getRenderTypes` callsites in individual render paths.
- `BakedModel` directly lists `net/neoforged/neoforge/client/extensions/IBakedModelExtension`, while `IDynamicBakedModel` extends `BakedModel` and declares custom `getQuads`. The actual model override behavior and mod-dispatch must be proved per representative compatible loaded mod; a generic static method-name list is not enough.

Original target compiled **callsite count is not the same as number of executions or rendered faces**. References to the external `hackersense/OptiFine-Source` tree remain comparative Forge/OptiFine source only, not replacement for these original NeoForge21.1.215 compiled artifacts. In particular, the selected static original classfile paths here do **not** prove missing grass, chain or sign faces in Planet running client.

## 3/4 — Existing Planet owner code and why Phase2 needs this work

Current Planet runtime implementation source verified in branch `2.0`:

1. [`PlanetBakedModelRotation`](../../src/main/java/dev/planetary/client/render/PlanetBakedModelRotation.java) wraps original `BakedModel` and delegates three-argument and NeoForge five-argument (`ModelData`, `RenderType`) `getQuads`; `OrientedModel` converts the queried physical cull direction to source-local and calls `QuadTransformers` then reconstructs `BakedQuad` with transformed vertices, original tint/sprite/ambient flag and physical `Direction`. The original model object is not modified. Weak model/quad caches are keyed by base model or quad identity and local Planet face; no dynamic model texture cache invalidation has been proved. This is SOURCE, not a bug proof.
2. `PlanetBakedModelRotation.orientForBlock` enters special `SurfaceSeamModel` path **only for `SpreadingSnowyDirtBlock` with multiple candidate faces**. At an outward seam `SurfaceSeamModel` reuses the original model's local `UP` quads and rotates them to that candidate physical face. This is **specific to a vanilla block family**, while a previously user-reported missing/asymmetric side surface bug applies to arbitrary blocks. The implementation may be insufficient for a general seam policy; the symptom's cause remains **UNKNOWN**, and *do not blindly generalize top quads to every block*. Need producer-side quad vs culling/AO/UV/tint diagnosis across material categories.
3. [`ModelBlockRendererPlanetMixin`](../../src/main/java/dev/planetary/mixin/ModelBlockRendererPlanetMixin.java) modifies only the target tesselation path, uses `PlanetClientRenderFrame.stateFrameAt` and candidate faces and has a narrowed `PoseStack.translate` override for pointed dripstone. Applies only if actually woven into client; JUnit compilation is not proof of an applied Mixin or other renderer overrides.
4. [`PlanetBlockRenderCulling`](../../src/main/java/dev/planetary/client/render/PlanetBlockRenderCulling.java) maps source and neighbor **different local directions**; calls source skipRendering and NeoForge external hiding hooks; then caches face Boolean under (`state`, `neighborState`, `sourceLocalSide`, `targetLocalSide`) WITHOUT `BlockGetter`/world/positions/BlockEntity/model epoch. 2048-element ThreadLocal LRU capacity is not invalidation. Model-data/dynamic mod face visibility context remains untested; earlier `3R-2j` proved piston **collision** varies with BE, not its face occlusion.
5. [`PlanetClientRenderFrame`](../../src/main/java/dev/planetary/client/render/PlanetClientRenderFrame.java) falls back from **any non-`Level` `BlockGetter` to the active `Minecraft.getInstance().level`** for local frame and candidate faces; target `RenderChunkRegion` is non-Level `BlockAndTintGetter` and holds an explicit originating Level+`modelDataSnapshot` (proven `3R-2k/l`). AE2 `FacadeBlockAccess` can independently wrap getters; Create `VirtualRenderWorld` is an independent Level. This is a SOURCE-verified provenance **risk**, not demonstrated real client race/failure.
