[NeoForge BlockBehaviour patch](https://github.com/neoforged/NeoForge/blob/3cae64530de368936d4c07497d3f0a25e2f9ffec/patches/net/minecraft/world/level/block/state/BlockBehaviour.java.patch) explicitly deprecates context-free `BlockStateBase.rotate(Rotation)` in favor of context-aware extension. **Do not declare** the world-aware overload automatically called by vanilla `StructureTemplate`; the comparative `StructureTemplate` still uses `state.mirror(mirror).rotate(rotation)`, and its own processor hook is extended by NeoForge. Check actual generated target and callsite, not Javadoc alone.

NeoForge comparative 1.21.1 [StructureTemplate patch](https://github.com/neoforged/NeoForge/blob/3cae64530de368936d4c07497d3f0a25e2f9ffec/patches/net/minecraft/world/level/levelgen/structure/templatesystem/StructureTemplate.java.patch) introduces **six-argument template-aware** `processBlockInfos(ServerLevelAccessor,BlockPos,BlockPos,StructurePlaceSettings,List,StructureTemplate)`. It permits mod processors to REPLACE/SKIP/REWRITE the block and its state before physical placement. See [C7 ABI test](../../src/test/java/dev/planetary/world/Phase23C7WorldgenStructureCommandAsmContractTest.java). Template rotation is a **physical structure transform**, not “rotate every state relative to whichever Planet face user is currently on.” Distinguish explicit authored state in `/setblock`/`/fill`, clone and machine schematic direct writers.

## 2/4 — lifecycle, alternate writers, cross-face semantic invariants

1. **Input:** retain world physical ray/hit `BlockPos` and `Direction` unchanged. Identify *source* author (PLAYER/DISPENSER/COMMAND/STRUCTURE/WORLDGEN/CONTRAPTION/FOREIGN), frame at **target BlockPos**, authored property domain and chart/transport provenance. No blanket “all north means tangent north.”
2. **Initial orientation:** `BlockItem.place -> getPlacementState` can dispatch into `CrafterBlock/JigsawBlock` or `StandingAndWallBlockItem` chooses a standing vs wall variant; `getStateForPlacement` may derive yaw and pair of orthogonal axes. For Create, property can be authored by adjacent block or wrench post-placement rather than vanilla default.
3. **Canonical representation:** on each Planet face `front` and `top` live in local frame with `top != front/opposite(front)`; `FrontAndTop.fromFrontAndTop` only accepts legal pair. `ROTATION_16` is 0..15 in a **tangent plane**, not 16 independent physical Directions; item yaw conversion and face chart basis must be explicit. Neighbor source->target chart crossing needs transport before writing.
4. **P35 transformation:** pure `BlockStateBase.rotate/mirror` dispatches to per-block virtual owner; NeoForge context-aware `IBlockStateExtension.rotate(LevelAccessor,BlockPos,Rotation)` is separate, may use external level and position and mod override. Actual `StructureTemplate` applies processor then `mirror` then `rotate` of state at a **physically transformed** destination, and then writes it. Do NOT apply second rotation on entry to `Level.setBlock` or silently overwrite explicit structure-authored orientation.
5. **Post-place:** `BlockItem.place` may apply `DataComponents.BLOCK_STATE` after initial getStateForPlacement; BE metadata, NBT or mod callbacks can independently modify orientation after placement. Jigsaw structure connectors, crafter signal ports, beam model, sign text and banner/skull BER follow **different phase owners**, not magically corrected by a state property conversion.
6. **Reload/foreign:** `WorldGenRegion`, `StructureTemplate`, guidebook `Level` and Create virtual contraption world are not automatically bound to Planet current `Minecraft.level`. Save/load stores canonical BlockState and BE data; renderer transforms physical quads separately (C11–15). C15 explicitly found foreign render region context fallbacks.

## 3/4 — deepest SAFE shared semantic boundary / version portability

| Classification | Owner contract and decision |
| --- | --- |
| **PHYSICAL_DO_NOT_TOUCH** | `BlockPos`, clicked world normal, `Level.setBlock`, generic `Direction`, structure transform origin/mirror/rotation, `Rotation`/OctahedralGroup global meaning, foreign/virtual `Level`, BE capability sides and mod physical graph. |
| **SHARED_SAFE** | Explicit `PlanetPlacementIntent` and **typed property-domain** `PlanetStateOrientation` composition for source->target frame: `FACE_6`, `HORIZONTAL_4`, `AXIS_3`, `FRONT_TOP_12`, `TANGENT_ROTATION_16`. Stable math and provenance independent of Minecraft version. The optional runtime API does NOT exist yet as a complete universal implementation. |
| **OPT_IN_ALGORITHM** | Per declaring-owner support for `CrafterBlock/JigsawBlock` orthogonal pair, ROTATION_16 yaw quantization and block-specific baseline, contextual NeoForge rotation, manual wrench/programmatic state rewrites; preserve mod callbacks and numeric property legality. |
| **MOD_INDEPENDENT** | Create custom `POINTING`, `TrackShape`, client render BE/BER and loaded Iris/virtual scene; complete 3A source inventory != actual loaded mod override audit. Unknown block/writer stays PHYSICAL unless opt-in intent provided. |
| **PORTABLE_ADAPTER** | Java core frame algebra + orientable property semantics; thin target1.21.1 adapters for `FrontAndTop/RotationSegment/StateDefinition`, NeoForge `IBlockStateExtension`, `BlockItem`, `StructureTemplate` and Mixin descriptors. Avoid raw global `BlockState.rotate` interception. |

**Why lower/global is unsafe:** `Rotation` is used for physical structures, mod tracks/contraptions, explicit item authoring, internal state serializations and foreign Levels. Monkeypatching it changes world semantics and breaks mod overrides. **Why upper/block-by-block is insufficient:** Create and arbitrary mods can add different enum/angle domains with independent entrypoints and after-place modifications; a few vanilla target Mixins alone cannot cover them. The lowest reusable **safe** point is *intent + property-domain typed semantics*, while preserving polymorphic block owner dispatch.

Implementation owner `2.4A` (state/property placement); `2.4D` (state transforms and direct use); Phase9 template/structure; Phase3 sign/banner/skull renderer; Phase7A crafter redstone; Phase10 arbitrary mod extension. No runtime implementation in this research-only packet.
