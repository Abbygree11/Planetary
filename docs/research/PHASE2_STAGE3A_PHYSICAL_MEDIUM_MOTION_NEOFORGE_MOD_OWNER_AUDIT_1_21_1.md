## Full family-level call paths

**Falling:** `FallingBlock.onPlace/updateShape → Level.scheduleTick(physical blockpos) → FallingBlock.tick` tests physical below + world minHeight then `FallingBlockEntity.fall`; source block transforms to entity. Entity falls/moves according to entity phase, then landing/drop/BlockState restoration invokes per-material behavior: sand/gravel inherited ColoredFallingBlock, concrete powder hydration via `ConcretePowderBlock.onLand`, DragonEggBlock uses falling delay5 plus independent click/attack teleport in bounded physical random 3D coordinates/worldborder. Handling a falling entity on a rotated-face local gravity requires Phase7 entity gravity, not a global `BlockPos.below` rewrite and not a randomTick only fix.

**NeoForge custom hydration:** patched `ConcretePowderBlock.shouldSolidify` checks `BlockState.canBeHydrated(BlockGetter,sourcePos,FluidState,fluidPos)`, including down/side checks and neighbor face solidity. Pinned `FallingBlockEntity.java.patch` uses same hook for original physical location and fast-motion fluid clip hit. Hardcoded WATER fails mod fluids; direct block lookup may use wrong state on landing. The call's source+fluid target positions must remain distinct physical facts. Correct hook availability at exact NeoForge21.1.215 remains a mandatory binary patch check.

**Fluid and columns:** `LiquidBlock` water/lava LEVEL[0..15] delegates `randomTick` to FluidState; `onPlace/updateShape/neighborChanged` schedule **fluid type ticks**, not owner BlockState `tick`; actual flow/drop/slope/source creation graph lives in `FlowingFluid`, owned Phase5. NeoForge comparative `FluidInteractionRegistry.canInteract` governs interaction instead of vanilla-only lava state hardcoding; `EventHooks.canCreateFluidSource` and `FlowingFluid.canConvertToSource(FluidState,Level,BlockPos)` must be preserved; don't remap all FluidStates. `BubbleColumnBlock` synthetic no-Item DRAG state propagates physically UP from support below through contiguous source-water or existing bubble column; tick+updateShape schedule block+water ticks; `MagmaBlock` and `SoulSandBlock` schedule own 20-tick bubble source update above. NeoForge comparative `BlockState.getBubbleColumnDirection()` allows custom source, not just hardcoded MAGMA/SOUL_SAND. Entity buoyancy/above-water exit logic is an independent entity-body/local gravity Phase7 and particle Phase3/4 owner.

**Graph/support/entity:** `ScaffoldingBlock.getDistance` uses physical DOWN for supported origin then four physical horizontals, not universal 3D attachment. It tracks BOTTOM, DISTANCE0..7 and WATERLOGGED; own 1-tick delay decides FALLING_ENTITY vs destruction vs state refresh. Its creator is **ScaffoldingBlockItem**, whose custom extended item placement bypasses naive BlockItem. Collisions depend on `CollisionContext.isAbove/isDescending` using physical Y; local player frame / physics needs separate explicit adapter. `MudBlock` and `SoulSandBlock` collision shape 14/16 while sturdy support shape full; `DirtPathBlock` own above-support + 1-tick revert to dirt, collision 15/16. `WebBlock.entityInside` applies slowdown to entity intersecting physical block volume, not BlockState `randomTick`.

**TNT world-block/entity author switch:** powered neighbor/onPlace, flint/fire charge useItemOn, burning projectile, explosive chain, unstable player removal activate a new `PrimedTnt` entity; vanilla BlockState UNSTABLE remains a property. NeoForge comparative `TntBlock.java.patch` funnels ignition via **`BlockState.onCaughtFire(state,Level,BlockPos,nullable physical face,nullable igniter)`** and must not be bypassed by direct private vanilla explode call. Actual PrimedTnt movement/collision physics belongs Phase7; no BlockItem-only solution.
