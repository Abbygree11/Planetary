## 2/4 — original item preview and independently mod-owned `BlockEntityWithoutLevelRenderer`

**Two dispatch paths are distinct from world BER**:
1. `ItemRenderer.render(ItemStack, ItemDisplayContext, ...)` handles vanilla model render passes and the *custom item* path. NeoForge [official ItemRenderer.java.patch comparator](https://github.com/neoforged/NeoForge/blob/3cae64530de368936d4c07497d3f0a25e2f9ffec/patches/net/minecraft/client/renderer/entity/ItemRenderer.java.patch) routes custom models to **`IClientItemExtensions.of(stack).getCustomRenderer().renderByItem`**, while non-custom passes use `BakedModel.getRenderPasses(stack,..)` / `getRenderTypes(stack,..)`. The `BlockEntityWithoutLevelRenderer` subclass may be a mod class and can operate with **no valid `Level` and no physical `BlockPos`** (inventory GUI, hotbar, item in hand/ground/frame, preview); `ItemDisplayContext` and caller `PoseStack` are *not* equivalent to Planet's block canonical state frame.
2. `BlockRenderDispatcher.renderSingleBlock` has its **own** custom renderer lookup and BEWLR invocation for block-item states, as previously proved by [Phase2 2.3C13 exact original API](PHASE2_STAGE3C13_ALTERNATE_BER_FLUID_INSTANCING_SHADERS_ASM_1_21_1.md). `BlockEntityRenderDispatcher` chooses an installed renderer by **BlockEntityType** in a world render pass ([3R-4D target JVM](PHASE3_R4D_NEOFORGE_BER_PROVIDER_REGISTRATION_MOD_OWNER_1_21_1.md)), but BEWLR is keyed through **client item extensions** and **not** equivalent to BE provider. Never globally wrap `BlockEntityRenderDispatcher.render` or BEWLR `PoseStack` together.

**NeoForge mod extension source comparator** [`IClientItemExtensions`](https://github.com/neoforged/NeoForge/blob/3cae64530de368936d4c07497d3f0a25e2f9ffec/src/main/java/net/neoforged/neoforge/client/extensions/common/IClientItemExtensions.java) explicitly declares `getCustomRenderer(): BlockEntityWithoutLevelRenderer` and offers independent `applyForgeHandTransform`, `renderHelmetOverlay` (HUD) and `of(ItemStack/Item)` registration lookups. [`RegisterClientExtensionsEvent.registerItem`](https://github.com/neoforged/NeoForge/blob/3cae64530de368936d4c07497d3f0a25e2f9ffec/src/main/java/net/neoforged/neoforge/client/extensions/common/RegisterClientExtensionsEvent.java) allows a mod-owned `Item` extension. Existing 2.3C-14 confirms `ItemInHandRenderer` and `ItemEntityRenderer` independent camera/actor physical origins; do not treat all `ItemDisplayContext` frames as world BlockPos.

**Patch point guideline for future implementation:** only adapt world-context *block-to-local geometry author* where a source Level / chart is valid, and otherwise delegate original item/GUI renderer without blind gravity rotation; if a custom renderer requires an explicit mod world context, source it from the renderer's own getter, not global `Minecraft.getInstance().level`. Preserve model tint/RT/lighting/UV without imposing block normals on GUI previews. These are design constraints, **not new code installed**.
