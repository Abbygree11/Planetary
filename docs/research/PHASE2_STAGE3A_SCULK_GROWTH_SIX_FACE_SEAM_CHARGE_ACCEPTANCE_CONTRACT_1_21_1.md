## 2. What exactly does “18 non-corner neighbors” mean?

[`SculkSpreader.ChargeCursor.NON_CORNER_NEIGHBOURS`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkSpreader.java#L225-L236) selects each physical integer `(dx,dy,dz)` in `[-1,0,1]^3` where **at least one coordinate equals zero and not all are zero**:

- **6 axis-adjacent** offsets: exactly one non-zero axis, Manhattan distance 1.
- **12 two-axis diagonals**: exactly two non-zero axes, Manhattan distance 2.
- **0** source offset, **0** three-axis body-diagonals: all three non-zero coordinates excluded (**8** such offsets).

Thus 6 + 12 = **18**, independent of whether a Minecraft Planet block lies at one of the real cube's 12 **face edges** or 8 **triple-face corners**. The two distinct meanings of “corner” MUST NOT be conflated.

[`getValidMovementPos`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkSpreader.java#L382-L410) takes a freshly randomized copy of the 18 offsets, queries **actual `LevelAccessor.getBlockState`** at physical target, requires `target.getBlock() instanceof SculkBehaviour`, and [`isMovementUnobstructed`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkSpreader.java#L412-L448) checks:

- Axial neighbor: `distManhattan == 1` ⇒ automatically unobstructed for this method.
- Two-axis neighbor: compute one intermediate path along each non-zero physical axis. At least **ONE** alternate `isUnobstructed` must pass (`||`, **NOT** `&&`); `isUnobstructed` checks whether the intermediate block is **not** sturdy on the direction facing back toward the source. A blocked alternative may be bypassed through the other.
- If a candidate has `SculkVeinBlock.hasSubstrateAccess`, break early. Otherwise loop can remember a previous **valid** SculkBehaviour target and return it at end. Do NOT assert “no substrate => cursor cannot move.”
- The `hasSubstrateAccess` implementation [uses `BlockTags.SCULK_REPLACEABLE`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkVeinBlock.java#L170-L189) specifically. Even in **worldgen mode**, this *movement preference* query is NOT simply the same as `spreader.replaceableBlocks() = SCULK_REPLACEABLE_WORLD_GEN` for **actual conversion**. Preserve the distinct tags or prove intentional policy with game tests.

**Boundary decision:** the offsets and obstruction ray are **already physical cube coordinates**. The current local gravity's `PlanetBlockFrameContext.step` is a *different algorithm* and cannot replace these 18 physical candidates without altering the vanilla neighborhood, random order, alternate obstruction and target selection. A future product feature may deliberately introduce a seam-aware charge path, but it must define explicit additional graph edges, no-duplicate target handling and parity/regression tests; this Stage 3A source audit does **not** claim such an implementation is automatically correct.

## 3. Physical, canonical-local, transported-chart and feature-space coordinates

Project code independently inspected at current branch head: [`PlanetFace`](https://github.com/Abbygree11/Planetary/blob/2.0/src/main/java/dev/planetary/topology/PlanetFace.java), [`PlanetBlockStateFrame`](https://github.com/Abbygree11/Planetary/blob/2.0/src/main/java/dev/planetary/world/PlanetBlockStateFrame.java), [`PlanetBlockFrameContext`](https://github.com/Abbygree11/Planetary/blob/2.0/src/main/java/dev/planetary/world/PlanetBlockFrameContext.java), [`PlanetBlockNeighborQuery`](https://github.com/Abbygree11/Planetary/blob/2.0/src/main/java/dev/planetary/world/PlanetBlockNeighborQuery.java), [`PlanetBlockRuntime`](https://github.com/Abbygree11/Planetary/blob/2.0/src/main/java/dev/planetary/world/PlanetBlockRuntime.java). These are **existing utilities**, NOT proof source Sculk classes have been wired to them.

| Domain | What stays true | Correct type of adapter |
|---|---|---|
| `PHYSICAL_BLOCK` | Real `BlockPos(x,y,z)` is unique for game storage, chunk `(x>>4,z>>4)`, BlockStates, block entities, cursor `pos`, `setBlock` and target deduplication | Never create separate face-indexed aliases for shared edge/corner physical blocks |
| `CANONICAL_BLOCK_STATE` | [`PlanetBlockStateFrame.resolve`](https://github.com/Abbygree11/Planetary/blob/2.0/src/main/java/dev/planetary/world/PlanetBlockStateFrame.java#L38-L55) chooses face *solely from physical BlockPos*, not how arrived | For growth-oriented outward-up meaning, vein face/support and target state, translate local direction using source/target own canonical frame |

**Real six-face base vectors**, derived from current actual `PlanetFace`:

| Canonical face | Local UP → physical | Local EAST → physical | Local SOUTH → physical | Local DOWN → physical |
|---|---|---|---|---|
| `POS_Y` | +Y | +X | +Z | −Y |
| `NEG_Y` | −Y | +X | −Z | +Y |
| `POS_X` | +X | −Y | +Z | −X |
| `NEG_X` | −X | +Y | +Z | +X |
| `POS_Z` | +Z | +X | −Y | −Z |
| `NEG_Z` | −Z | −X | −Y | +Z |

**Worked source-local example:** `SculkBlock` at interior canonical `POS_X`; source-local UP is physical **+X**, while vanilla `pos.above()` is physical **+Y**. Those are **different target physical cells**. In a future local-growth adapter, target must be the single real `pos.relative(localUPPhysical)`, after evaluating target eligibility, rather than creating both cells. `SculkVeinBlock` at that same place still tracks an actual six-face attachment; target and source can have *different canonical frames* at an edge, so the face's property meaning is resolved separately for each block.

**Triple corner example:** two or three distinct entry traversal charts reach exactly the same physical `BlockPos`. `PlanetBlockStateFrame.resolve` returns the same canonical frame and BLOCK ID; cursor aggregation uses **that physical BlockPos as key**, not arrival chart or current velocity/gravity face. An individual `SculkSpreader.ChargeCursor` still holds `pos,charge,decayDelay,updateDelay,facings`; the `facings` are `Set<Direction>` and [serialized via vanilla Direction codec](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkSpreader.java#L238-L255). A future adapter must define **explicit face-property provenance during any chart transport** and must never silently reinterpret serialized physical face bits as newly local-facing bits on reload. Be especially careful not to combine “one canonical state” with “one cursor”: multiple distinct physical cursor objects may legitimately occupy **one** position due to vanilla worldgen or merge-limit rules. The invariant is **no duplicates arising solely from Planet aliasing**, not a false “one cursor per BlockPos” rule.

## 4. Growth target vs local density search: 9×3×9 is not 18 neighbors

[`SculkBlock.canPlaceGrowth`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkBlock.java#L94-L123) examines vanilla `cursorPos.above()` (allowed AIR or WATER with water fluid), then counts both `SCULK_SENSOR` and `SCULK_SHRIEKER` inside **inclusive physical cube** from `(-4,0,-4)` to `(+4,+2,+4)` relative to source cursor: **9×3×9 = 243** candidate cells, rejects **more than 2** nearby sensors/shriekers. That is not the `SculkSpreader` cursor movement graph and does not count SCULK/VEIN/CATALYST as density hits.

**Proposed face-local growth contract:** for a single-face interior, calculate the candidate target from **canonical source-local UP** and rotate the two tangent ±4 axes and local normal layers 0..+2 into **physical cells**. The arithmetic has exactly 243 offsets in the interior and preserves vanilla counts on POS_Y. Across seams, each evaluated sample is mapped into the **actual physical cell** under an explicit traversal/generation policy; deduplicate coincident physical sample positions for density counting, and do not count a boundary alias twice. No existing Sculk integration or test validates this proposal. Choose precisely whether the window follows transported local tangents beyond the seam or is centered in the original canonical source chart; decide and record with Phase-8/9 feature-space ownership before coding. **Do not preclaim 243 *distinct* reachable physical cells on every edge/corner.**

[`SculkBlock.attemptUseCharge`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkBlock.java#L30-L74) checks charge and a rate gate first; if beyond `noGrowthRadius` and eligible growth, it pays `growthSpawnCost` **even if** the subsequent spawn-chance check fails. It authors SENSOR/SHRIEKER at the chosen physical target through `LevelAccessor.setBlock` (item callbacks NOT used); chooses shrieker with `1/11` **conditional growth selection**, `CAN_SUMMON = spreader.isWorldGeneration`; target fluid influences WATERLOGGED of the **new block**, not SculkBlock. Physical charge source distance (`closerThan`, `distSqr`, decay penalty) must not be blindly replaced with a face-atlas distance. If a product-specific curved-surface metric is desired, that's a separate, explicit policy needing regression evidence.

**Spreader mode parity:** [`createLevelSpreader`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkSpreader.java#L66-L74) uses `SCULK_REPLACEABLE`, (cost 10, no-growth radius 4, rate 10, extra decay 5); worldgen uses `SCULK_REPLACEABLE_WORLD_GEN`, (cost 50, radius 1, rate 5, extra decay 10). These tag differences apply to vein **replacement**; movement's `hasSubstrateAccess` has its own tag check as above. Worldgen [`ChargeCursor.update`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkSpreader.java#L348-L354) limits cursor spread by **physical XZ-only distance to origin**: it constructs `new Vec3i(origin.x,cursor.y,origin.z)` and compares `closerThan(...,15.0)`, **not Euclidean distance including vertical Y**. On POS_X/±Z/NEG_Y faces, an unadapted worldgen cutoff may bias growth. This is a distinct Phase-8/9 radius/feature-coordinate question, not the `noGrowthRadius` condition above.

## 5. Vein graph, replacement, discharge and physical entity displacement

[`SculkVeinBlock.attemptPlaceSculk`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkVeinBlock.java#L113-L169) uses a shuffled physical six-`Direction` loop, checking an *existing* source vein face, then `target = veinPos.relative(face)` and membership of target state in `spreader.replaceableBlocks()`. On success: `setBlock(target,Blocks.SCULK.defaultBlockState(),3)`, [`Block.pushEntitiesUp`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkVeinBlock.java#L142-L146), sound, `veinSpreader.spreadAll` and discharge neighboring vein faces. This is distinct from SculkBlock making a sensor/shrieker. When **false**, `SculkVeinBlock.attemptUseCharge` still may reduce charge (normal/worldgen rate), but does not write new sculk.

The source [`SculkVeinBlock.regrow`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkVeinBlock.java#L55-L84) uses actual adjacent support, re-adds legal face properties and WATERLOGGED from target fluid. [`onDischarged`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkVeinBlock.java#L87-L110) removes faces whose actual neighbors are sculk and may replace fully disconnected vein with AIR or WATER. [`SculkVeinSpreaderConfig.stateCanBeReplaced`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkVeinBlock.java#L233-L266) excludes SCULK, catalyst and MOVING_PISTON; on two-axis paths tests intermediate physical sturdy support; rejects non-water fluids and FIRE. [`MultifaceSpreader`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/MultifaceSpreader.java#L85-L115) implements SAME_POSITION, SAME_PLANE, WRAP_AROUND states, where `SpreadPos(pos,face)` must refer to exactly one physical target and its target canonical support side; **a normal BlockState may have several legal face bits**, and an existing vein may legitimately be updated more than once during different legal source calls. Avoid false “one setBlock call ever” uniqueness claims.

**Proposed seam contract:** source vein faces and target block canonical faces are not interchangeable. Resolve physical neighbor in the owning BlockState frame, inspect the actual target BlockState/collision and the target's canonical inward side, then choose legal attached face property. Do not pass raw source-local `Direction` across a rotated seam and interpret it as target-local without mapping; do not lose legal world-physical contacts either. A path-dependent traversal frame is allowed only *temporarily* for step calculation, not persisted as a second state. Pure `SculkBlock` has no FACING/BE/WATERLOGGED state, so this applies to **VEIN and newly grown SENSOR/SHRIEKER**, not a non-existent SCULK orientation property.

`Block.pushEntitiesUp` uses vanilla physical world-up movement, which is **not** guaranteed to displace entities outward along Planet local UP; this belongs to Phase 7 entity/displacement. Separate Phase 5 WATERLOGGED and flows: the vein and new sensor/shrieker can waterlog; SCULK cannot. Never mark particle orientation, collisions, or water flow “PASS” from source alone.

## 6. Charge lifecycle, merge, save/load, tick gates, worldgen rounds

[`SculkSpreader.addCursors`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkSpreader.java#L145-L160): split charge into chunks each **at most 1000**, admit **at most 32 cursor objects**. Truncation at capacity and nontrivial merge behavior are vanilla semantics, not a Planet data-loss bug by default. [`load/save`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkSpreader.java#L117-L143): serialize list under `cursors`, cap 32 on load; each cursor's physical `pos`, charge (0..1000), `decay_delay` (0..1), `update_delay` and optional Direction `facings`. Preserve these exact stable world-cell positions over server reload and seam crossing.

[`updateCursors`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkSpreader.java#L163-L221) updates each cursor, removes exhausted charges (level event 3006), records physical `Map<BlockPos,...>` and sums grouped charges; merges **only in non-worldgen mode**, **only if sum <=1000**. In worldgen mode or overflow, the same physical `BlockPos` may correspond to multiple actual cursor objects; they are **not phantom face aliases**. Event 3006 encodes strength and `MultifaceBlock.pack(facings)` by Direction ordinal; if future adapters change face interpretation, particle client decoding and persisted direction bits require Phase 3 plus Phase 2 checks. Do not “dedupe to one cursor per block” and accidentally remove legitimate vanilla charge.

[`ChargeCursor.shouldUpdate`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SculkSpreader.java#L293-L311) non-worldgen checks `ServerLevel.shouldTickBlocksAt(p_222327_)` and the caller supplies **spreader's origin position**, not `this.pos`. Preserve the current actual vanilla tick-gating argument unless intentionally changing policy and testing with physical chunk states; worldgen skips this exact check. Catalyst [`serverTick`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/entity/SculkCatalystBlockEntity.java#L33-L55) drives level-mode `updateCursors`, independent of BLOOM scheduled block tick. Worldgen [`SculkPatchFeature.place`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/levelgen/feature/SculkPatchFeature.java#L23-L79) seeds cursors and loops configured rounds/attempts, with `spreadFlag` true only during `spreadRounds` and `clear()` per round; it directly writes a catalyst and extra shrieker where eligible, but writes SCULK indirectly via vein. A naive always-spread`=true` adaptation would change the configured worldgen algorithm.

**Non-Planet invariant:** when there is no Planet field (`PlanetBlockRuntime.fieldAt` returns empty), do not perform any frame conversion. Preserve normal world XZ growth, 18-neighbor movement, worldgen cutoff, BlockItem, template/command and chunk addressing unchanged.
