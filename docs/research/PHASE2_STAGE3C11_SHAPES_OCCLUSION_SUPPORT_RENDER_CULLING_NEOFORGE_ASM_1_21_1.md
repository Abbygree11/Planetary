## 1/4 — actual declaring owners, subclasses, exact method families and consumers

| Original owner | Distinct methods / writer-consumers | Coordinate contract |
| --- | --- | --- |
| `BlockStateBase.getShape` simple/context | Delegates to polymorphic `BlockBehaviour.getShape(state,getter,pos,CollisionContext)`; raycast outline | Canonical in block algorithm, physical shape to callers on Planet-owned world positions |
| `BlockStateBase.getCollisionShape` simple/context | May serve `BlockStateBase.Cache.collisionShape` for stable states; dynamic contextual query goes to block override; `BlockCollisions` and entities read it | PHYSICAL world VoxelShape and AABB; preserve Shapes.block identity fast path |
| `BlockStateBase.getVisualShape/getInteractionShape` | Visual raycast vs interaction override, clip contexts and individual mod block geometry | PHYSICAL outer API shape, not render quad generation |
| `BlockStateBase.getBlockSupportShape/isFaceSturdy` with `SupportType.FULL/CENTER/RIGID` | Dynamic state or cached support flags and VoxelShape face tests, plus `Block.canSupportCenter`; survival of torches/levers/rails | Support block's own CANONICAL **local side toward source** while physical neighbor BlockPos stays physical |
| `BlockStateBase.getOcclusionShape/getFaceOcclusionShape` | Cached state face shape indexed by original `Direction.ordinal()`, or dynamic `Shapes.getFaceShape` of original occlusion volume | Face local for state property lookup; renderer must map source and target own local sides |
| `Block.shouldRenderFace` | `state.skipRendering(neighborState,physicalDirection)`, then **NeoForge neighbor.hidesNeighborFace** + `state.supportsExternalFaceHiding`, then canOcclude and `Shapes.joinIsNotEmpty(sourceFace,targetFace,ONLY_FIRST)` | Physical adjacent cell, transported local face on *both* sides at gravity seam; unknown mods might implement each hook |
| `Shapes.mergedFaceOccludes` | Geometric occlusion between two physical `VoxelShape` faces | Uses PHYSICAL crossing side, distinct from local canonical support |
| `BlockCollisions` and `ClipContext` | Iterate physical cells, ask state collision/outline/visual shape and intersect physical entity/ray boxes | May query foreign BlockGetter/fake region not a bound Level |
| `ModelBlockRenderer.tesselateBlock(...,ModelData,RenderType)` | NeoForge model data/types, AO selection, culling, BakedQuad directional sides and vertex output | CLIENT; physical BakedQuad directions + original mod ModelData/RenderType must survive |
| `BakedModelWrapper` and mod BakedModel/BER | Dynamic quads, CTM and model data, custom block entity renderers and Flywheel/Render Engines | Mod own owner separate from vanilla renderer; cannot safely force vanilla wrapper on all renderers |

**Nested shape querying matters:** BlockBehaviour defaults for `getCollisionShape`, `getVisualShape`, `getBlockSupportShape`, `getOcclusionShape` may call `BlockStateBase.getShape` or `getCollisionShape` internally. Rotating each method RETURN independently would apply the transform multiple times. Current `BlockStateShapeMixin` enters a ThreadLocal scope at HEAD and uses `finishPhysical` at the outermost physical shape query for outline/collision/visual/interaction and `finishCanonical` for support/occlusion. A stable mod BlockState virtual dispatch must remain underneath it.

## 2/4 — lifecycle, cache invariants, support/neighbor and rendering bypasses

**Support and neighbor:** `PlanetBlockSupportQuery` maps source-local support direction to actual adjacent physical supportPos and computes target block's *own* canonical side toward source. `PlanetBlockSupportRuntime` invokes vanilla `isFaceSturdy(SupportType.RIGID/FULL)`/`Block.canSupportCenter`, defaulting to PHYSICAL behavior for foreign `LevelReader`. A `BlockStateBase.Cache` computed through `EmptyBlockGetter` has neither physical Planet position nor chart; rotating that cache at construction would corrupt all states and mods. For dynamically position-dependent mod `getBlockSupportShape`, keep owner-declared dynamic override and never substitute a generic full cube.

**Culling:** `PlanetBlockRenderCulling` transforms the physical source direction and opposite target direction separately via `stateFrameAt`. Calls mod `skipRendering`, `hidesNeighborFace`, `supportsExternalFaceHiding`; `getFaceOcclusionShape` called for both states using *their own local direction* and `Shapes.joinIsNotEmpty`. Normal vanilla state-pair key has state1/state2/one Direction, unsafe across seams. Planet's cache currently holds `(sourceState,targetState,sourceLocalSide,targetLocalSide)`: this distinguishes seam-side frames but **does not include physical position, BlockGetter identity, mod render data or dynamic face geometry**. For dynamic/modded face shapes returning different geometry for same states depending on neighboring BlockEntity/pos, cache result may be stale **(code-level risk; no game reproduction)**. Phase3 must decide conditional bypass for dynamic blocks, full source/target scope or cache invalidation keyed by world/position/data; blanket addition of physical positions may have performance costs and must be proven by profiles/tests.

**Foreign-world render contexts:** `PlanetClientRenderFrame.stateFrameAt` receives many `BlockGetter` implementations from chunk render regions; when not a `Level`, it falls back to `Minecraft.getInstance().level`. This is necessary for many true client chunk render regions, but **may map a foreign / contraption / fake BlockGetter to active Planet client Level**, applying a transform it did not opt into. Keep typed provenance and fallback constraints; no global `BlockGetter` frame conversion or modded-world hijack.

**AO/light:** `ModelBlockRenderer` samples physically adjacent positions for AO and light; `PlanetBakedModelRotation` returns a BakedModelWrapper view with rotated quad vertices, packed normals, physical BakedQuad.direction and unchanged UV/tint/RenderType/ModelData. However AO sampler corner semantics, `getShadeBrightness`, `getLightBlock`, `useShapeForLightOcclusion` and per-position model data must be tested independently, not conflated with Block.shouldRenderFace. User-visible odd side-face shadows do not mean a specific ASM mismatch. Third-party ConnectedTextures/CTM/BakedModel can independently hide a face via `skipRendering`/model-data or custom rendering; vanilla frame-aware culling is necessary but not sufficient.

**Cross-mechanism bypasses:** liquid shape and `FlowingFluid.canPassThroughWall` (StageC10), piston `VoxelShape` swept entity collisions (StageC8), structure updates and Shape propagation (C7/C4), light/biome/occlusion caches, custom BER and model renderers, block neighbor `updateShape` are independent owners. BLOCK ID inventory does not certify any of these; complete tests must include arbitrary mod subclasses/override families and physical fake-world controls.

## 3/4 — deepest safe shared boundary and mod compatibility

| Classification | Mechanisms | Safe rule |
| --- | --- | --- |
| **PHYSICAL_DO_NOT_TOUCH** | `BlockPos`, `Direction`, `BlockCollisions` iteration, raw AABB/raycast, `Shapes.mergedFaceOccludes` on already physical forms, `EmptyBlockGetter` state caches, real chunk regions and fake-world access | Mods and vanilla worlds need the same physical coordinates and unrotated model-registration caches |
| **SHARED_SAFE** | `BlockStateBase` virtual shape dispatch, `SupportType` plus mod support overrides, NeoForge `hidesNeighborFace/supportsExternalFaceHiding`, ModelData/BakedModelWrapper/RenderType extension | Preserve original virtual mod callbacks and model content; adapter converts only representation at caller boundary |
| **OPT_IN_ALGORITHM** | Planet-owned shape query and local support, source+target frame/face occlusion and seam-aware traversal, optional mod dynamic-shape culling opt-in with context | Typed `PlanetShapeQueryContext` /`PlanetOcclusionEdge`: original BlockGetter provenance, physical source/target, both chart frames, source/target local faces, physical collision side |
| **MOD_INDEPENDENT** | ConnectedTextures/CTM, Create ConnectedGlass, AE2 QuartzGlass, custom BER, Flywheel/renderer, dynamic block geometry and fake contraption Levels | Do not intercept/substitute generic BakedModel or `Level` globally; retain external mod algorithms |
| **CLIENT_RENDER** | ModelBlockRenderer AO, dynamic light, BakedQuad normals, custom render types, occlusion culling and tinted quads | Phase3 implementation and dedicated client tests separate from Phase2 support/geometry |

**One layer deeper is unsafe:** rewriting all `VoxelShape` instances, `BlockPos.relative`, `BlockGetter.getBlockState`, world-wide `isFaceSturdy` direction or original `BlockStateBase.Cache` would rewrite physical game and foreign mod semantics. **One layer shallower is insufficient:** patching slab or torch shapes individually misses eight common BlockState shape APIs, dynamic mod subclasses, cached occlusion, cutout/translucent glass, support lookup, NeoForge face hiding and baked-model AO. Current general Planet boundaries are the better platform; strengthen position/frame provenance and dynamic-cache policy later.
