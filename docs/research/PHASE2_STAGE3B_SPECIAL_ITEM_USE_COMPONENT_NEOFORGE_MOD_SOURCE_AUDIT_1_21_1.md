## 4/4 — deepest safe Planet contract, exact disposition, planned integration gates

### Semantic author contract (design only, not implemented)

`ItemSourceIntent`: `(authorKind, javaConcreteOwner, itemId, hitPhysicalBlockPos, hitPhysicalFace, hitWorldPoint, sourcePlayerBodyFrame?, virtualOrRealLevelProvenance, finalPhysicalTargetBlockPos?, originalState, proposedState, statePropertyOrigin, actionAbilityOrEvent, mutationKind, resultEventOwner)`.

- **SHARED_SAFE**: record physical author provenance on ingress (`Item.useOn/use`, `BlockItem.place`, `getToolModifiedState`, `BonemealEvent`) WITHOUT globally changing callbacks, default unknown third party to PHYSICAL. Choose canonical target frame only for **semantically authored state** with known property legality; do not assume every callback in a physical Level means a gravity-relative direction.
- **OPT_IN_ALGORITHM**: tool conversion support, `physicalClickedFace→targetCanonicalLocalAttachment` when a real author means attachment; local above/below for planting/rope and aquatic surface only when algorithm or mod explicitly opts in; late property component conversion only if producer provenance proves physical values. Pinned vanilla method names are adapter sites, not instructions to copy entire Java implementations.
- **MOD_INDEPENDENT**: Farmer's Delight RiceItem/RopeItem/MushroomColonyItem independent overrides, RiceBlock growth. Mod may register a mechanism adapter for `local-up`, semantic surface planting etc. A vanilla inherited base Mixin **does not** cover any overridden `useOn`/`updatePlacementContext`/`getPlacementState` unless it hooks the still-invoked common inner function.
- **PHYSICAL_DO_NOT_TOUCH**: raw `BlockHitResult`, collision, world bounds, `Level.setBlock`, `BlockPos.relative`, raw `BucketPickup`/`LiquidBlockContainer`/`FluidType`, physical side in world rays, original registry and state-serialization formats, foreign/fake levels, mod tool abilities/events and permission checks.

**Why not one level deeper?** Patching Level/BlockPos/Direction or globally mapping `getClickedFace` corrupts true physical space and independent worldgen/foreign mods. **Why not one level shallower?** Vanilla named-item hooks miss other vanilla tools and overriding mod subclasses, NeoForge ItemAbilities/BonemealEvent and independent use paths. Correct seam combines a version-independent typed state/author policy plus multiple thin, version-specific callsite adapters tied to the real owning dispatch, not a single universal placement interception.

### Explicit handoff and NOT DONE items

- Phase2: item writer provenance, state legality/local support; `ItemNameBlockItem` inherited state + direct useOn tools; guards around `BLOCK_STATE`, clicked/target frame, block survival/growth and multiblock.
