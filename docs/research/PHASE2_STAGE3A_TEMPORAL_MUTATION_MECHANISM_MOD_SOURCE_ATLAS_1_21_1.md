**Distinctions for "over time":** `randomTickSpeed=0` freezes stochastic block change, not scheduled ticks nor BE server progress; unloaded chunks do not accrue arbitrary offline time unless a mod specifically records/implements it; fluid random and fluid scheduled queues are independent of block state author. ### 2. Copper is a useful reference algorithm, but not the universal clock

`WeatheringCopper` extends `ChangeOverTimeBlock<WeatherState>`; its four grades `UNAFFECTED→EXPOSED→WEATHERED→OXIDIZED` are separate registered **Block types**, not one block with an `age` property. Shared `ChangeOverTimeBlock.changeOverTime` first gates `RandomSource.nextFloat()<0.05688889F`. `getNextState` scans `BlockPos.withinManhattan(pos,4,4,4)` and ignores nonmatching enum type and own cell; a **younger neighbor blocks progression**; counts equal/older neighbors then `f=(older+1)/(older+equal+1)`, chance `f²*getChanceModifier()` with unweathered modifier0.75 and other grades1.0. The vanilla implementation's path traverses **PHYSICAL Manhattan cells**; not a gravity-local tangent/varying metric. Next ID from `WeatheringCopper.NEXT_BY_BLOCK`, preserves shared properties via `withPropertiesOf` (not all arbitrary NBT/BE). Terminal OXIDIZED isRandomlyTicking=false; waxing swaps to *other registered classes* and removes the weathering callback. It is not a real-world wall-clock exposure or rain counter.

Vanilla map also connects copper slab, stairs, door, trapdoor, grates and bulbs already researched under their own **different** class owners; do not count them twice. Stage34 original exact 24 includes 12 unprotected solid, 4 unprotected grate, 4 unprotected bulb, 4 **waxed** bulb. The latter is specifically `CopperBulbBlock`, not a randomTick weatherer, yet `LIT/POWERED` state changes via `onPlace/neighborChanged/checkAndFlip` from incoming redstone power. A standard `WeatheringCopperBulbBlock` implements **both** redstone changes and weathering changes independently. `WeatheringCopperGrateBlock` uses `WaterloggedTransparentBlock.getStateForPlacement/updateShape` for WATERLOGGED and scheduled water fluid tick; oxidation preserves WATERLOGGED through withPropertiesOf. Other waxed solids may be plain `Block` in the original registry rather than one of the 24 rows; original 241-class census remains frozen; no automatic promotion.

**Other direct AUTHOR paths (not randomTick):** `AxeItem` undo weather stage or wax via tool modification; `HoneycombItem.WAXABLES` changes block registration + copies shared properties; `LightningBolt` uses `WeatheringCopper.getFirst` or `getPrevious` via physical proximity; tool state mutations and creative/commands/StructureTemplate/WorldGenLevel/ItemStack `BLOCK_STATE` late override and dispenser/bonemeal can bypass `randomTick`; mod extensions `getToolModifiedState` and fake-world contexts may differ. Door two halves, orientations/multi-block, copied cap metadata and waterlogged shape require **owner-specific invariants** on block-ID swap — not all mutations copy arbitrary metadata.

### 4. Runtime architecture contract (FUTURE; no code here)

**SHARED_SAFE:** immutable `TemporalMutationContext(sourcePhysicalBlockPos,source/target canonical gravity frames,origin,worldTime/tickType,sourceState,allowedMutationIntent,dimension/chunk/Level provenance,randomSource)` and interface for mod opt-in. Observability at stable `BlockState.randomTick`/scheduled `tick`/BE ticker dispatch can carry **physical source identity** without rewriting callbacks or assuming active in unloaded chunk. Stable semantic helpers for `localAbove`, support target, six-neighbor graph, frame-transport after block-ID replacement; adapters remain thin and target-version-aware. Allow per-algorithm policies to select local surface/tangent, world-physical volume, or global sky/time. No default random ticking of all registered classes or changing randomTickSpeed.

**OPT_IN_ALGORITHM:** gravity-bearing grow-up/down, per-cell support, local rain exposure/sky policy if chosen, spreading across edge transport, multi-block atomic grade replacement, mod-defined neighbor sampling and interval progress; explicit contract and fixtures. **MOD_INDEPENDENT:** actual mod subclasses override lifecycle, custom world event handlers and BE timers (Caverns rail/wall; Farmer rice/soil/cooking), mod-wide data-driven growth registry; cannot promise vanilla `WeatheringCopper` intercept covers custom rule. **PHYSICAL_DO_NOT_TOUCH:** `ServerLevel.tickChunk`, scheduled queue timestamps, `LevelChunkSection` actual physical chunk, global BlockPos/Direction, raw AABB, random RNG sample counts, `FluidState` identity, `Level.setBlock`, `NeighborUpdater` physical origins and `BlockEntity` world positions. More generic deeper auto-rewrites break vanilla no-Planet, other mods and replay determinism. Shallower patch e.g. copper only misses entire crop/ice/ore/BE/time graph.

**Cross-face mutation rules:** movement/mutation author first resolves actual source identity, sampling neighborhood policy (physical Manhattan for vanilla copper; gravity-local growth per opted plant), target position/chart and target legal state set; preserves common properties only when both states allow them; synthetic patch/state swaps must not leave orphan BE; late item/structure placement may originate beyond tick engine. Track per-source root and physical target at 12 seams/8 corners. No duplicate cross-edge write or synthetic "accelerated timer" on repeated chunk load. This is a design contract, not implemented code.
