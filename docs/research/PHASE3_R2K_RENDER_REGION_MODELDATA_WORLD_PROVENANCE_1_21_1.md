## 2/4 — Confirmed region → model-data producer chain and precise target ownership

**Original target compiled JVM facts**, with exact signatures and access flags in artifact:

1. `RenderRegionCache.createRegion(Level,SectionPos)` forwards to overload `createRegion(Level,SectionPos,boolean)`, which calls `Level.getModelDataManager():ModelDataManager`. Producer Level is an explicit argument, not global client singleton.
2. `RenderChunkRegion implements BlockAndTintGetter`, **does not extend Level**, and contains fields `level:Level`, `chunks:RenderChunk[]`, and `modelDataSnapshot:Long2ObjectFunction<ModelData>`, plus chunk coordinate indices. `RenderChunkRegion.getBlockState` delegates to `RenderChunk.getBlockState` and `getBlockEntity` delegates to `RenderChunk.getBlockEntity`. `getModelData(BlockPos)` is a concrete method on the region, with a snapshot field rather than an implicit current live client `BlockEntity`. The exact snapshot construction/invalidator requires further instruction trace, not guessed here.
3. `RenderChunkRegion.getLightEngine` and `getBlockTint` delegate to the region's `Level`; the physical light and tint owner remains distinct from local-coordinate shape transformation.
4. `SectionCompiler` has four-/five-argument `compile` overloads taking `RenderChunkRegion`. The five-argument implementation calls region `getBlockState`, `getBlockEntity` and `getModelData`, then `BakedModel.getModelData` and `getRenderTypes` through JVM `INVOKEINTERFACE=185`.
5. `SectionCompiler.compile` invokes `BlockRenderDispatcher.renderBatched` with a parameter list explicitly containing `BlockAndTintGetter`, `BlockPos`, `ModelData` and `RenderType`. This proves the caller *has* a region/geometric source parameter; bytecode signature alone doesn't prove every caller passes the same instance at runtime or the exact local-face projection.
6. `ClientLevel` itself has a `modelDataManager:ModelDataManager` field. Unlike `RenderChunkRegion`, it is a `Level` and may be Planet-gravity-bound; the same *interface* is not authority to substitute it for a separate region or mod getter.

Consequently, **there is a specific legal target-version render region carrying originating `Level`**. Planet's `PlanetClientRenderFrame` currently treats *all* non-Level getter types, including that region, as fallback requests for `Minecraft.getInstance().level`. In an ordinary active-world chunk compile this often happens to be the originating world; with asynchronous rebuild after a world switch, alternate world/dimension, foreign preview or mod facade it is **not proven equivalent**. This is a source-verified compatibility risk rather than an established gameplay failure.

## 3/4 — Compatible real mod source bypasses: Create/Ponder and AE2

[30-route detailed source/bytecode/bypass matrix](PHASE3_R2K_REGION_MODELDATA_PROVENANCE_OWNER_MATRIX_1_21_1.tsv) includes target engine, renderer worker, NeoForge API, game fake-world and mod model paths. Version provenance is the *released* compatible set from `3R-2h`: Create 6.0.10 (released tag mc1.21.1-6.0.10 / build neo 21.1.219), Ponder 1.0.82, AE2 19.2.18 — **not** Create development 6.0.11/Ponder 1.0.85 or modern AE2 26.3. Mod source is pinned and released binaries/JVM declarations were independently verified in the previous stage, but **none of these mod JARs was loaded in the Minecraft/Planet client for this packet**.

- **Create [`VirtualRenderWorld`](https://github.com/Creators-of-Create/Create/blob/mc1.21.1-6.0.10/src/main/java/com/simibubi/create/foundation/virtualWorld/VirtualRenderWorld.java):** extends `Level`, stores independent `Map<BlockPos,BlockState> blockStates` and `Map<BlockPos,BlockEntity> blockEntities`, separate light engine. Its override `getModelData(pos)` queries **its own** BE map and returns `blockEntity.getModelData()` or `ModelData.EMPTY`. Merely extending `Level` does **not** mean this object was bound to PlanetGravityRuntime's physical world.
- **Create [`ContraptionWorld`](https://github.com/Creators-of-Create/Create/blob/mc1.21.1-6.0.10/src/main/java/com/simibubi/create/content/contraptions/ContraptionWorld.java) + Ponder `WrappedLevel`:** Contraption getter returns `contraption.getBlocks().get(pos)`, else AIR; the wrapper delegates other facilities to underlying Level. A single instance may combine independent block-space data with parent world facilities. Explicit provenance must include **which subsystem owns `pos`**.
- **AE2 [`FacadeBlockAccess`](https://github.com/AppliedEnergistics/Applied-Energistics-2/blob/neoforge/v19.2.18/src/main/java/appeng/client/render/cablebus/FacadeBlockAccess.java)** implements `BlockAndTintGetter` but is not a `Level`; `getBlockEntity` delegates to wrapped getter. Its `getBlockState(pos)` returns fake facade state **only if `this.pos == pos` (reference identity)**, otherwise calls wrapped getter. This exact old-source condition matters for deciding whether copying/normalizing `BlockPos` retains facade substitution. It is **not yet proof of a rendered issue**, and broad changes to `BlockPos` identity could be a compatibility regression.
- **AE2 [`GlassBakedModel`](https://github.com/AppliedEnergistics/Applied-Energistics-2/blob/neoforge/v19.2.18/src/main/java/appeng/client/render/model/GlassBakedModel.java)** `getModelData` computes `GlassState` with source `BlockAndTintGetter` and neighbor `getAppearance` calls. Its `getQuads` uses passed ModelData and face to choose/suppress quads. Geometry beyond `Block.shouldRenderFace` cannot be captured solely in Planet's VoxelShape occlusion cache.
- **AE2 [`CableBusBakedModel`](https://github.com/AppliedEnergistics/Applied-Energistics-2/blob/neoforge/v19.2.18/src/main/java/appeng/client/render/cablebus/CableBusBakedModel.java)** stores original `BlockAndTintGetter` in private record `FacadeModelData(EnumMap<Direction,ModelData>,BlockAndTintGetter level)` during `getModelData` and subsequently passes `facadeData.level` into facade mesh generation during `getQuads`. This is a concrete **carrier of source-world provenance through `ModelData`**, independent of ambient `Minecraft.getInstance().level` and potentially across worker/lifecycle boundaries. It is *not* evidence of an actual Planet rendering regression.

**Non-implementation architecture decision for later stages:** `BlockAndTintGetter` as a type does not identify a Planet binding. Provenance should derive from *producer origin* `(bound Level identity, coordinate mapping, region snapshot epoch, getter wrapper chain)`, not from a global active-world singleton; unknown foreign getter should not implicitly inherit Planet gravity. The verified region's `Level` field is a possible explicit source; independent mod wrappers need opt-in adapters and exact coordinate mapping. Preserve source/neighbor local frames separately over all 12 seams and eight corners; physical lighting remains physical and custom model quads follow their own orientation owner in Phase3B/3D. No runtime implementation selected.
