## 1/4 Dispenser and falling entity source owners

Mojang-named comparative source pinned to hackersense/OptiFine-Source commit b77c5c6995874f6cf2755bc5234428906b337b75; not exact patched 21.1.215 bytecode.

- DispenserBlock.dispenseFrom gets the inventory slot and registered DispenseItemBehavior; DispenseItemBehavior.bootStrap installs many independent special behaviors, frequently anonymous execute implementations. Not all call Item.useOn. ShulkerBoxDispenseBehavior calls BlockItem.place with a player-less DirectionalPlaceContext on the actual physical front cell, using conditional physical below support to select synthetic hit direction. Bucket behaviors call DispensibleContainerItem.emptyContents, fire and bonemeal use independent helpers, honeycomb mutates via HoneycombItem.getWaxed, skull/pumpkin can setBlock directly, water potion turns the physical front cell into mud. Default behavior drops an item Entity, not a block.
- DropperBlock overrides dispenseFrom and getDispenseMethod: default item ejection or direct HopperBlockEntity inventory transfer at physical front cell. Physical capability/inventory side must remain physical; do not conflate dropper with dispenser state placement.
- FallingBlock.tick schedules a fall, FallingBlockEntity.fall captures BlockState in an Entity and replaces original physical source with its FluidState legacy block. Its tick/landing flow checks canBeReplaced(new DirectionalPlaceContext(level,target,DOWN,ItemStack.EMPTY,UP)) as a **replacement predicate**, not a BlockItem.place call; checks physical support, attempts direct Level.setBlock(target, carriedState,3), invokes Fallable.onLand or onBrokenAfterFall, may drop an item and restores BlockEntity data via loadWithComponents. ConcretePowderBlock.onLand can transform into concrete. Existing Planetary falling gravity adapters are not full landing acceptance.
- Later official NeoForge 1.21.1 source patch 3cae64530de368936d4c07497d3f0a25e2f9ffec: DispenseItemBehavior adds stack-sensitive container emptyContents and getToolModifiedState FIRESTARTER_LIGHT / flammability callbacks. FallingBlockEntity uses BlockState.canBeHydrated instead of only water. This patch SHA is **comparative, not proven exact 21.1.215**.

## 2/4 Features, structures, templates, commands

- Feature.place(FeaturePlaceContext) and Feature.setBlock/safeSetBlock receive WorldGenLevel and LevelWriter; concrete TreeFeature, ChorusPlantFeature, PointedDripstoneFeature and EndPlatformFeature use direct worldgen writes in their own algorithms. Feature writes are **WORLDGEN** coordinates, not a player body frame. No global WorldGenLevel or Level.setBlock rotation.
- StructurePiece.placeBlock independently positions and rotates/mirrors block state. StructureTemplate.processBlockInfos transforms physical target positions and applies a chain of StructureProcessor implementations, possibly suppressing or substituting blocks; placeInWorld mirrors/rotates states, writes physical cells, clears/restores BlockEntity NBT/components, handles waterlogging, notifies/upgrades neighbors, may spawn entities. No BlockItem.getStateForPlacement or late item component logic is invoked. StructureBlockEntity.placeStructure triggers this pipeline; JigsawBlockEntity generates via oriented connectors. NeoForge's later StructureTemplate patch introduces processor overload with actual StructureTemplate argument and process(...) dispatch: do not bypass these mod extensions.
- BlockInput.place used by SetBlockCommand/FillCommand accepts **explicit author-specified BlockState and optional NBT**, runs updateFromNeighbourShapes and writes physical ServerLevel cells; CloneCommands independently copies physical blocks and BE data with placeholders. Never reinterpret explicit command literals as player-local look direction. Rotation/Mirror for structures is different from a hypothetical Planet six-face local rigid transform; opt-in and source/destination frames must be explicit.

## 4/4 Deepest-safe shared contract and acceptance

**SHARED_SAFE**: typed WorldBlockAuthoringContext carrying author kind, real/virtual/worldgen Level provenance, source physical position, target physical position, raw click normal (if any), optional source frame, final target canonical state frame, original/proposed BlockState, legal property author intent, processor/BE/tick/event flags. Observe raw writes but never globally change them.

**OPT_IN_ALGORITHM**: shulker synthetic orientation, falling-entity local support/landing, local plant/feature surface intent, rigid structure source/destination frame conversion only where owner requests it. **MOD_INDEPENDENT**: Create's schematics/contraptions and AE2 region swaps; future opt-in hooks when the actual mod is loaded. **PHYSICAL_DO_NOT_TOUCH**: world BlockPos/Direction, Level.setBlock, NeighborUpdater, raw water/FluidState, command literals, chunk geometry, WorldGenLevel sampling, foreign/virtual Levels and physical capability sides.

Deeper global Level/BlockPos rewrites break foreign worlds and independent mod algorithms; shallower named-item patches miss anonymous dispenser behaviors, Feature subclasses, template processors and falling entities. Preserve NeoForge extension dispatch, BE components, worldgen algorithm, collision, fluids, user explicit state and permissions.

**Cross-phase:** Phase2 author/BlockState/support; Phase3 models/BER; Phase5 fluid; Phase7 fall/entity; Phase7A redstone/logistics; Phase8 worldgen; Phase9 structures/portals; Phase10 mod interoperability. No runtime changes. All future 6-face/12-edge/8-corner, vanilla regression, CI/ASM and loaded-mod gameplay tests NOT RUN; separate exact 21.1.215 runtime binary stage 2.3C.
