### SnowLayerBlock: physical snow support, one-cell stacking, light and shape

[`SnowLayerBlock`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/SnowLayerBlock.java#L25-L181), [`Blocks.SNOW`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/Blocks.java#L2237-L2251).
- Initial `LAYERS=1` and legal 1..8. `canBeReplaced`: if held item is not own snow item OR layers ≥8, may be replaced only when layers==1; if same item and layers<8, may stack when click isn't replacing-clicked-on-block, otherwise requires **clicked face world `Direction.UP`**. Do not replace with universal “any touch adds layer” rule. `getStateForPlacement` increments **same real existing physical BlockPos** `min(layers+1,8)`, otherwise delegates to `Block.getStateForPlacement`. Late Item `DataComponents.BLOCK_STATE` can legally modify LAYERS after initial placement; no BE.
- `canSurvive` examines **real source physical `pos.below()`**, then `BlockTags.SNOW_LAYER_CANNOT_SURVIVE_ON` rejects, `SNOW_LAYER_CAN_SURVIVE_ON` accepts, otherwise checks whether **below block actual collision shape is full on world `Direction.UP`** or below is snow layers==8. The CAN/CANNOT tag branches are distinct, do not simplify to “any full block”.
- `updateShape` returns AIR if `canSurvive` false, any neighbor recomputation can trigger. `randomTick` if **LightLayer.BLOCK brightness >11** drops resources/removes snow. No biome-temperature threshold in this particular *randomTick* algorithm.
- `getShape/getCollisionShape/getBlockSupportShape/getVisualShape` are distinct. Collision uses index `LAYERS-1` whereas outline shape uses LAYERS; five layers stop being land-pathfindable (`LAYERS<5`). Actual shape/face-full support belongs Phase3; do not merely tilt snow texture and claim collision/pathfinding fixed. Not every “layer shape on local floor” is representable by a single stored property and a physically unrotated vanilla AABB.

### PowderSnowBlock: no stored orientation/levels, non-water powder bucket, entity-specific collision

[`PowderSnowBlock`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/PowderSnowBlock.java#L34-L190), [`Blocks.POWDER_SNOW`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/Blocks.java#L6754-L6764). Zero state properties, inherited ordinary placement/survival/neighbor/updateShape/randomTick. **Not a FallingBlock subclass**, despite `FallingBlockEntity` branch in collision code. The collision shape returns **empty** ordinarily; it can use `FALLING_COLLISION_SHAPE` for an entity `fallDistance>2.5`, and tests `EntityCollisionContext`/`FallingBlockEntity` or `canEntityWalkOnPowderSnow` for collision. Special boots `Items.LEATHER_BOOTS` and `EntityTypeTags.POWDER_SNOW_WALKABLE_MOBS`, plus `CollisionContext.isAbove(...)/!isDescending` affect walk surface. These source calls are Phase7 entity physics, not bare item/block state orientation.
- `entityInside` sets stuck motion multiplier to physical `Vec3(0.9,1.5,0.9)`, `setIsInPowderSnow(true)`, cancels on-fire and conditional in-block destruction if eligible burning entity; client particles use **world X/Z motion and world block-Y+1**. `fallOn` has sound thresholds 4 and 7, `getVisualShape`/`getOcclusionShape` empty, `isPathfindable` true. All local gravity and camera/render offsets need separate Phase3/7 policy; no proven universal “snow fall” implementation.
- `BucketPickup.pickupBlock` directly replaces powder snow with AIR, emits 2001 and returns `Items.POWDER_SNOW_BUCKET`. This is NOT FluidState WATER, not SnowLayerBlock stacking and not default BlockItem consumption semantics.

### IceBlock and FrostedIceBlock: two sources of water, different tick algorithms

[`IceBlock`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/IceBlock.java#L18-L81), [`FrostedIceBlock`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/FrostedIceBlock.java#L19-L130), source [`Blocks` ICE / FROSTED_ICE registration](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/level/block/Blocks.java#L2252-L2265).
- `IceBlock.meltsInto()` returns Blocks.WATER default state. `IceBlock.randomTick` checks `getBrightness(LightLayer.BLOCK,pos)>11 - blockState.getLightBlock(...)` then `melt`. `melt` **removes block** in dimension `ultraWarm()`; otherwise **sets WATER and calls `neighborChanged` explicitly** at same real physical BlockPos. This is a phase transition, not generic WATERLOGGED property.
- `IceBlock.playerDestroy` first delegates to super, then if tool lacks `EnchantmentTags.PREVENTS_ICE_MELTING`, in ultraWarm `removeBlock(pos,false)`; otherwise checks *physical `pos.below()` state* `blocksMotion() || liquid()` before placing WATER. Distinguish *harvest-created water conditional on below* from *environment/randomTick melting into water*. It is false to say IceBlock always creates water whenever broken.
- `FrostedIceBlock` inherits `IceBlock.randomTick` declaration but its **registration lacks `randomTicks()`**. Its own `onPlace` schedules **60..120 inclusive** initial block tick. `tick` condition is (`nextInt(3)==0 || number of physical 6-neighbor frosted ice blocks <4`) AND brightness threshold `getMaxLocalRawBrightness >11-AGE-getLightBlock`; `slightlyMelt` advances age 0→1→2→3 then calls inherited `melt` at AGE 3. If melt succeeds, iterate **six physical `Direction.values()` neighbors**, age them and schedule 20..40 ticks if not melted. Otherwise own tick scheduled 20..40 ticks. Distinct `neighborChanged`: if changed neighbor block IS frosted ice and source has **fewer than 2** physical frosted ice neighbors, `melt` immediately, regardless of a “surface local tangent” and without source `randomTick`; this is a different trigger from staged tick.
- `getCloneItemStack` of FrostedIceBlock returns **`ItemStack.EMPTY`**; no original `ITEM.placed_block` mapping, no vanilla direct Silk-touch/frosted-ice BlockItem author. A configurable enchantment effect such as [`ReplaceDisk`](https://github.com/hackersense/OptiFine-Source/blob/b77c5c6995874f6cf2755bc5234428906b337b75/1.21.1/net/minecraft/world/item/enchantment/effects/ReplaceDisk.java#L42-L59) can write a BlockState in an x/z `BlockPos.betweenClosed` disk, subject to predicates; this code is an **algorithmic capability**, not proof which installed datapack/enchantment effect has actually configured FROSTED_ICE. Require exact datapack configuration and creation path evidence before claiming specific Frost-Walker wiring. `/setblock`/`/fill`/`StructureTemplate` can supply legal state directly independently.
