## 1/4 — exact item placement and second-cell owner

| Family and owner | Physical flow / effective method | Status scope |
| --- | --- | --- |
| `BedItem.placeBlock(BlockPlaceContext,BlockState):boolean` | Declared override: **single first-half** `Level.setBlock(target,state,26)`. **Does not call `BlockItem.placeBlock` super.** | Exact compiled callsite asserted by test |
| `BedBlock.getStateForPlacement(BlockPlaceContext):BlockState` | Chooses initial **foot** and horizontal `FACING`, checks physical second-cell replacement/world border before first-half write. | Original source + target method descriptor asserted |
| `BedBlock.setPlacedBy(Level,BlockPos,BlockState,LivingEntity,ItemStack)` | Second author. From final foot `FACING`, calls `BlockPos.relative(direction)` then `Level.setBlock(head,HEAD-state,3)`, `blockUpdated`, `updateNeighbourShapes`. | Exact compiled callsites asserted |
| `DoubleHighBlockItem.placeBlock(...)` | Declared override: PRE-CLEAR `context.getClickedPos().above()` to water/air with flags 27, then `INVOKESPECIAL BlockItem.placeBlock` for initial cell. **It is not itself the upper-half writer.** | Exact `above` and super-callsite, write order asserted |
| `DoublePlantBlock.setPlacedBy(...)` | Creates **upper** via physical `above`, `copyWaterloggedFrom`, `Level.setBlock(...,3)`. | Exact compiled callsite asserted |
| `DoublePlantBlock.placeAt(LevelAccessor,BlockState,BlockPos,int):void` | Independent direct **two-cell** writer, used by worldgen/bonemeal; does NOT require `BlockItem.place` or `setPlacedBy`. | Exactly two setBlock invokes asserted |
| `DoorBlock.setPlacedBy(...)` | Own two-part placement callback, independent of `DoublePlantBlock` inheritance. Covers all 20 original door ITEM IDs via DoubleHighBlockItem, not trapdoors. | Exact owner/method and upper write checks |

**Important ordering:** `BlockItem.place` dispatches virtual `placeBlock`, then reads actual state and may apply explicit `DataComponents.BLOCK_STATE` and BlockEntity data/components **before** calling `Block.setPlacedBy`. Therefore final `FACING` and HALF property may differ from the original `getStateForPlacement` candidate after the initial second-cell obstruction check. This is a real source call-order hazard requiring semantic acceptance; do not silently drop explicit component values. It is **not** acceptable to reinterpret arbitrary ItemStack `FACING/AXIS/HALF` as physical if the producer intends canonical state, nor to ignore mod overrides.

## 2/4 — survival, maintenance, rollback, block entities

- `BedBlock.updateShape` couples `FOOT/HEAD` and copies OCCUPIED from neighbor, or removes invalid half; `getNeighbourDirection` is based on stored FACING (already a state-local semantic in Planet). `playerWillDestroy` independently removes partner in creative; `useWithoutItem` accesses second half via physical `relative(FACING)`; sleeping, respawn, pose/dismount, BER, sound and world physical AABBs have independent owners, recorded in [Stage3A bed audit](PHASE2_STAGE3A_BED_RESPAWN_ORIGINAL_OWNER_SLEEP_MOD_1_21_1.md). Exact `BedBlock.newBlockEntity` creates BE for placed bed; client rendering belongs to a separate stage.
- `DoublePlantBlock.getStateForPlacement` checks world `maxBuildHeight` and physical `above`; `canSurvive` checks physical `below` for UPPER, normal `BushBlock` support for LOWER; `updateShape` monitors axis Y physical adjacent half and removes invalid plants; `preventDropFromBottomPart` handles creative destruction and fluid restoration.
- `DoorBlock` independently overrides `getStateForPlacement`, `setPlacedBy`, `canSurvive`, `updateShape`, `neighborChanged` for signals, `playerWillDestroy` (drop prevention), interactive toggles and redstone. Mod copper doors can override temporal/redstone methods independent of placement. Do not treat `DoublePlantBlock` patch as inherited by doors.
- **Potential existing Mixin contract risk:** `BedBlockGravityMixin.planetary$localPairUpdate` and `DoorBlockGravityMixin.planetary$localPairUpdate` can return the input state and cancel at HEAD for other non-pair directions in an active Planet frame. This may suppress vanilla or NeoForge future/mod-specific `updateShape` processing for those callbacks; needs target-version semantic diff and in-game/mod acceptance, not blanket approval solely because handlers compile. Neither can be deemed a complete general multiblock solution.
- **Potential cross-frame pre-clear problem:** before any `DoublePlantBlock/DoorBlock.setPlacedBy` adaptation, `DoubleHighBlockItem` clears the **physical** `above()` cell, whereas the intended local upper cell may be different on Planet side/underside faces. A local second-half writer alone cannot retroactively undo unintended physical clearing. Treat pre-clear and final two-cell placement as a single typed owner-family lifecycle.
- `DoublePlantBlock` `copyWaterloggedFrom` and `placeAt` retain independent fluid state semantics; `BedBlockEntity` and late components must be checked at both physical block positions, not by assuming all vanilla BE values auto-duplicate.
- Event ordering and permissions remain NeoForge `BlockItem.place` side effects. A private copied implementation or global `Level.setBlock` rewrite might silently drop hooks, model ownership or modded block-entity behavior.

## 3/4 — deepest safe family boundary / mod compatibility

Source-pinned real mod comparator: **Comforts for MC 1.21.1** from [`illusivesoulworks/comforts@5ee1465755dcbfc0e47b5d53a1c61ad0b70cf178`](https://github.com/illusivesoulworks/comforts/tree/5ee1465755dcbfc0e47b5d53a1c61ad0b70cf178) (documented in [bed source audit](PHASE2_STAGE3A_BED_RESPAWN_ORIGINAL_OWNER_SLEEP_MOD_1_21_1.md)). Its base comfort/sleep classes are independently authored; declared NeoForge range includes 21.1.215 by metadata **only**; no compatible loaded mod JAR/gameplay result. Also source-pinned other modded door material variants in [Stage3A door audit](PHASE2_STAGE3A_DOOR_TRAPDOOR_FULL_OWNER_ITEM_REDSTONE_COPPER_MOD_1_21_1.md). Mod entity/structure writes and alternate ITEM overrides are not automatically covered by vanilla `BedItem` or `DoorBlock` Mixins.

| Mechanism | Disposition | Future safe semantic boundary |
| --- | --- | --- |
| Ordinary physical hit, BlockPos/Level.setBlock, numeric build height, world border | **PHYSICAL_DO_NOT_TOUCH** | Keep true chunk/block identity and all modded physics/foreign Level callers |
| Virtual `BlockItem.place` and `Block.setPlacedBy` dispatch | **SHARED_SAFE** for observation | Capture *final* actual BlockState, physical author/target, then narrow opt-in adapter |
| Multi-cell offset (head/upper) and delayed `BLOCK_STATE` | **OPT_IN_ALGORITHM** | Explicit source canonical frame + target physical position and transported canonical state, precheck and pre-clear both cells consistently |
| `DoublePlantBlock.placeAt`, structure, worldgen, bonemeal | **OPT_IN_ALGORITHM / WORLDGEN** | Pure typed two-cell pair construction; non-player author must explicitly choose its coordinate domain |
| Independent mod subclasses, virtual schematic levels and contraptions | **MOD_INDEPENDENT** | Caller-specific semantic declaration or per-family adapter; unknown physical by default |

**One level deeper is unsafe:** generic `BlockPos.above/relative`, `Level.setBlock`, `NeighborUpdater` changes would affect every physical simulation, worldgen and mod graph. **One level shallower under-covers:** adapting only `BedBlock` or `DoublePlantBlock` misses `DoubleHighBlockItem` pre-clear, late item components, doors/copper variants, worldgen `placeAt`, modded authors. The eventual version-independent semantic helper must represent a two-cell/linked-structure author transaction: initial and final author/provenance, physical clicked hit, independently canonical frames, transport direction, state/property legality, BlockEntity and fluid conservation; vanilla or NeoForge thin adapters then call it at actual proven owner seams.
