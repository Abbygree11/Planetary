## 2/4 — ModelDataManager: owner thread, refresh, bounded shallow snapshot

The *actual* original `ModelDataManager.<init>(Level)` records `Thread.currentThread()` in `owningThread`, sets the manager `level`, and creates `needModelDataRefresh` plus `modelDataCache` maps. Do **not** extrapolate that all worker methods are thread-safe or that every manager instance is necessarily constructed on the main thread just because it is a Minecraft client API; classfile proves identity of owning thread and explicit checks.

`snapshotSectionRegion(int,int,int,int,int,int)` **calls `isOtherThread()` and constructs `UnsupportedOperationException` for a non-owner**. On its accepted path, it creates `Long2ObjectOpenHashMap`, sets map default return value to `ModelData.EMPTY`, iterates section coordinates using `SectionPos.asLong(x,y,z)`, calls `refreshAt(sectionKey)`, and copies entries from `modelDataCache` into the newly created snapshot map using `Long2ObjectMap.putAll`; when the result is empty, it may use `ModelDataManager.EMPTY_SNAPSHOT`. This is a **copy of map associations/references**, not proven deep copies of individual `ModelData` objects. The region scope is expressed as six coordinate indices; exact physical bounds/loop inclusivity can be traced in the archived opcodes and are not invented from the descriptor alone.

`requestRefresh(BlockEntity)` separately checks `isOtherThread()` (throws `UnsupportedOperationException`), tests non-null BE and **BlockEntity.getLevel against manager.level** via `Preconditions.checkState`; marks `needModelDataRefresh` by `SectionPos.asLong(BE.getBlockPos())`. `refreshAt(sectionKey)` checks thread ownership, processes the pending positions and reads **the manager's stored Level.getBlockEntity(pos)**, tests removal, calls `BlockEntity.getModelData()`, and updates/removes matching per-section `modelDataCache` entries. There is an explicit null-payload exception path. These are **original compiled bytecode facts**, not proof that a foreign mod sends all refresh notifications at the right time.

**World/provenance consequence:** the manager deliberately ties its BE source, queue, and model-data snapshot to a particular `Level` and owning thread. A guessed ambient client Level would bypass that relation. The actual refresh epoch/worker observation timing and mutable ModelData payload sharing need later runtime acceptance.

## 3/4 — RenderRegionCache → RenderSection.RebuildTask → SectionCompiler lifecycle and bypasses

The exact call chain selected from 1,946 original instruction records:

1. `RenderRegionCache.createRegion(Level,SectionPos,boolean)` accepts the **explicit caller Level**, obtains `LevelChunk`/`RenderChunk[]` through `ChunkInfo`, calls **`Level.getModelDataManager().snapshotSectionRegion(...)`**, and creates `new RenderChunkRegion(Level,minChunkX,minChunkZ,RenderChunk[],Long2ObjectFunction<ModelData>)`.
2. `RenderChunkRegion` stores `level:Level` and `modelDataSnapshot` separately. Its `getModelData(BlockPos)` performs `GETFIELD modelDataSnapshot`, `BlockPos.asLong()`, and `Long2ObjectFunction.get(long)`; neither this method nor its original callsite infers `Minecraft.getInstance().level`. `getBlockState/getBlockEntity` resolve their `RenderChunk` through source position.
3. `SectionRenderDispatcher$RenderSection.createCompileTask(RenderRegionCache)` first cancels previous tasks; retrieves **dispatcher.level:ClientLevel** and `origin`; invokes `ClientHooks.gatherAdditionalRenderers(origin,Level)`; calls `RenderRegionCache.createRegion(dispatcher.level,SectionPos.of(origin),boolean)`, then passes constructed `RenderChunkRegion` into `new RebuildTask(...)`.
4. `RenderSection.rebuildSectionAsync` invokes `createCompileTask` then `SectionRenderDispatcher.schedule`. Therefore the original selected **code ordering** constructs a region/snapshot before the task is scheduled; this is not yet a dynamic assertion that every runtime callback executes on a specific thread.
5. `RebuildTask.<init>` stores its `region:RenderChunkRegion` and `additionalRenderers`. `RebuildTask.doTask` has early cancellation/neighbor checks, reads its `region` into a local and **writes its own region field back to null**, then calls `SectionCompiler.compile(SectionPos,RenderChunkRegion,VertexSorting,SectionBufferBuilderPack,List)` with the captured value. The null field is a reference-release action, **not** proof that snapshot contents immediately cease to exist. Async `CompletableFuture` and invokedynamic callback code processes results and possible cancellation.
6. `SectionCompiler.compile` reads region block states and BEs and `region.getModelData(pos)`, calls `BakedModel.getModelData(getter,pos,state,ModelData)` and `getRenderTypes`, delegates to `BlockRenderDispatcher.renderBatched(...BlockAndTintGetter,BlockPos,ModelData,RenderType)`, and passes the **explicit region** to `ClientHooks.addAdditionalGeometry`. NeoForge geometry hooks and mod baked quads can have independent position/face owners, so do not equate all rendered quads with Planet's `Block.shouldRenderFace` / shape cache.

**Important conceptual split:** the *original compiler* carries a concrete source getter/Level and a bounded manager snapshot through its task. **Planet `PlanetClientRenderFrame` still falls back to the current Minecraft client Level for any non-Level getter**, so it can discard this available origin for `RenderChunkRegion` and foreign `BlockAndTintGetter`. This is an independently source-verified possible provenance mismatch, **not a gameplay-reproduced rendering failure**. `PlanetBlockShapeRuntime.finishPhysical` conversely treats a non-Level getter as canonical. These code owners must be reconciled only after the full Phase3 research gate.

[40-row detailed original snapshot/refresh/worker/cancellation/mod bypass matrix](PHASE3_R2L_SNAPSHOT_WORKER_LIFECYCLE_OWNER_MATRIX_1_21_1.tsv) records source/target owners, evidence grades and open acceptance. Real 1.21.1 released Create `VirtualRenderWorld`, Ponder `WrappedLevel` and AE2 `FacadeBlockAccess`/`CableBusBakedModel` remain **source/ABI only** in this packet: Create has independent virtual BlockStates/BEs and ModelData; AE2 can substitute a facade using `this.pos == pos` object reference and carry the original getter inside `FacadeModelData`. Do not claim these mods were loaded or affected by the Planet code without a client test.
