### Placement, thickness and attachment — Phase2 per-cell semantic BlockState

- `getStateForPlacement` starts with player `BlockPlaceContext.getNearestLookingVerticalDirection().getOpposite()`, checks `calculateTipDirection` and tries the opposite if initial direction unsupported. `canSurvive` uses **physical supporting neighbor at `pos.relative(TIP_DIRECTION.getOpposite())`**, allows **`isFaceSturdy(...,TIP_DIRECTION)` OR another original pointed dripstone with same TIP_DIRECTION**; thus not simply `pos.below()`. `getStateForPlacement` computes `THICKNESS` from in-front same/opposite neighboring pointed tips; `isSecondaryUseActive` changes merging policy; sets WATERLOGGED based on target actual `getFluidState().getType() == Fluids.WATER`.
- `updateShape` enqueues actual WATER fluid tick whenever own WATERLOGGED=true. For non-vertical callback physical directions returns unchanged; for vertical, `TIP_DIRECTION=DOWN` with already scheduled block tick returns unchanged, else if support fails at `direction == TIP_DIRECTION.opposite`, schedules block tick **2 ticks for DOWN falling**, **1 for UP destruction**; otherwise recomputes THICKNESS (including merged tips). Actual `tick` destroys unsupported upward stalagmite; for downward stalactite invokes `spawnFallingStalactite`. Vanilla state vertical_direction domain has ONLY UP/DOWN, so on Planet ±X/±Z surface mapping must not assign illegal `EAST/WEST/NORTH/SOUTH` to it: proposed semantic "vertical" representation needs a **source/target canonical-frame-specific** mechanism preserving actual physical collision.
- `getShape` uses five THICKNESS-specific voxel shapes, DOWN/UP special TIP, horizontal randomized X/Z offset (0.125) while Y offset remains zero. Phase3 source canonical geometry/particle is separate from BlockState/Phase2.

### Falling, collision and damage — deep shared `FallingBlockEntity/Fallable/Entity.fallOn`

- `spawnFallingStalactite` traverses physical **`Direction.DOWN`** through successive downward dripstone states, spawns **one `FallingBlockEntity.fall` per block** until tip, sets `setHurtsEntities(max(1 + originY - tipY, 6), maxDamage40)` on tip and stops. `onBrokenAfterFall` event **1045**, `getFallDamageSource` yields **fallingStalactite**, `fallOn` for **UP + TIP** applies stalagmite fall damage `causeFallDamage(fallDistance + 2, multiplier 2, source stalagmite)`, else calls `super.fallOn`. Do NOT conflate block falling entity impact vs stationary UP tip entity landing.
- **Deepest SAFE shared runtime owner** is existing Planetary falling-block motion/physical collision/damage and `Fallable` callback **with explicit source canonical local gravity**; but vanilla `spawnFallingStalactite` world-DOWN chain traversal remains an independent owner requiring a targeted semantic column algorithm. Never globalize `FallingBlockEntity.fall` into a change to physical `BlockPos` or modded unrelated falling systems. Preserve earlier user-reported partial working falling-stalactite collision/damage; tests below are UNRUN for full Phase17 contract.
