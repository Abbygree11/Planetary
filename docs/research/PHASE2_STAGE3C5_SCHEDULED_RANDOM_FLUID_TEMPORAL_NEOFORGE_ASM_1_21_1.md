## 1/4 — actual owner and JVM dispatch contract

| Initiator and callback | Target behavior | Domain / separating assumption |
| --- | --- | --- |
| `ServerLevel.tick(BooleanSupplier)` → 2 `LevelTicks.tick(long,int,BiConsumer)` | First BLOCK, then FLUID, `max=65536` each, only `!debug && tickRateManager.runsNormally()` | Scheduled *wall game time* of currently ticked ServerLevel, not local gravity |
| `ServerLevel.tickBlock(BlockPos,Block)` | Re-read current `BlockState`; only call `BlockState.tick` if state `is(type)` | Queue must skip replaced block; underlying BlockState owner remains mod-overridable |
| `ServerLevel.tickFluid(BlockPos,Fluid)` | Re-read `FluidState`; only call `FluidState.tick` if `is(type)` | Distinct current-fluid identity |
| `LevelTicks.schedule(ScheduledTick)` | Chunk-aware `LevelChunkTicks`; dedup per type+position; `triggerTick`, `TickPriority`, `subTickOrder` | Storage/checks can also be called directly via `getBlockTicks/getFluidTicks`; no generic BlockItem dependence |
| `LevelTicks.tick` | `collectTicks → runCollectedTicks → cleanupAfterTick`; `hasScheduledTick` and `willTickThisTick` are separate lookups | Collection snapshot, ordering, tick-cap, per-chunk load, queries during in-flight callback |
| `ServerLevel.tickChunk(LevelChunk,int)` | `LevelChunkSection.isRandomlyTicking`, stochastic sampling of current `BlockState.isRandomlyTicking→randomTick` **and** `FluidState.isRandomlyTicking→randomTick` | **Separate random driver**; `LevelTicksMixin.schedule` cannot provide this. Chunk randomTickSpeed and sections matter |
| `BlockBehaviour.BlockStateBase.tick/randomTick` | Dynamic `getBlock().tick/randomTick` on concrete registered block instance | Inherited mod Block overrides work through virtual dispatch |
| `FluidState.tick/randomTick` | Dynamic `getType().tick/randomTick` on concrete Fluid | Fluid flow is NOT block scheduling; `FlowingFluid.tick` calculates new liquid, reschedules, spreads |
| `ChangeOverTimeBlock.changeOverTime/getNextState` | Independent default interface algorithm called by randomTick owner; physical `BlockPos.withinManhattan(pos,4,4,4)`; block-ID swap via `getNext` | Copper weathering is just one producer; interface uses 3D *physical* Manhattan sphere |
| `BlockEntityTicker` / `Level.tickBlockEntities` | Independent BE state clock with persistent NBT, recipes, machine states | Not driven by `BlockState.randomTick` nor `LevelTicks` |

The exact compiled test pins selected descriptors/callsites, the *two* `LevelTicks.tick` references, class-dispatch separation and `ServerLevel.tickChunk` randomTick. Do **not** claim exhaustive per-241-class bytecode coverage from that test.

## 2/4 — existing Planet runtime lifecycle and uncovered paths

Already implemented, directly read:

- [LevelTicksMixin](../../src/main/java/dev/planetary/mixin/LevelTicksMixin.java) intercepts `schedule(ScheduledTick)` (HEAD), `hasScheduledTick(BlockPos,T)` (HEAD), `willTickThisTick(BlockPos,T)` (HEAD), adds to `count()` (RETURN). Each is routed via [PlanetVanillaTickBridge](../../src/main/java/dev/planetary/world/PlanetVanillaTickBridge.java), which binds **two distinct actual LevelTicks objects** by identity to Planet block and fluid queues.
- [PlanetTickScheduler](../../src/main/java/dev/planetary/world/PlanetTickScheduler.java) has comparator `triggerTick`, priority ordinal and sub-tick order; prevents duplicate pair `(type,PlanetBlockPos)`, tracks `toRunThisTick`, removes running tick before callback and leaves ticks newly scheduled by callback for next collection. Some parity tests already exist: [PlanetTickSchedulerTest](../../src/test/java/dev/planetary/world/PlanetTickSchedulerTest.java), [PlanetVanillaTickBridgeTest](../../src/test/java/dev/planetary/world/PlanetVanillaTickBridgeTest.java). These tests are not live world/game events.
- [ServerLevelMixin](../../src/main/java/dev/planetary/mixin/ServerLevelMixin.java) has two `@Inject` handlers on `ServerLevel.tick`, `@At(INVOKE LevelTicks.tick(JILBiConsumer;)V,ordinal=0,shift=AFTER)` and ordinal 1. Each executes [PlanetWorldAccess](../../src/main/java/dev/planetary/world/PlanetWorldAccess.java) `runScheduledBlockTicks` or `runScheduledFluidTicks` with separate `maxTicks=65536`. These encode canonical `PlanetBlockPos` to virtual `BlockPos`, revalidate current BlockState/FluidState type and dispatch the *original* polymorphic callbacks.
- **Potential cap/fairness problem:** the ordinary LevelTicks driver can execute **up to 65536** block and 65536 fluid ticks each, then Planet's independent queue can execute up to **another 65536** for each. Thus real load/ordering differs from a single unified per-type capped vanilla queue. The four sub-steps do not implement a fix; preserve exact server scheduling/cap semantics at future adapter boundary, including chunk-loaded priorities.
- **Potential random driver coverage gap:** `ServerLevel.tickChunk` samples actual `LevelChunkSection`. Neither `PlanetVanillaTickBridge` nor `PlanetWorldAccess.runScheduled*Ticks` covers stochastic ticks of **Planetary's independent virtual `PlanetBlockStateStore`**. The reviewed existing code has no equivalent `PlanetWorldAccess.runRandomBlockTicks`/fluid method. Therefore random mutation (copper weathering, grass spread, sapling/crop growth, leaf decay and mod autonomous blocks) **must not be marked functional** merely because scheduled ticks run; need separate source/section-sampling integration or proof virtual entries flow through vanilla chunk sections, with `randomTickSpeed`, chunk load and distribution preserved. This is a source-observed coverage gap, not a gameplay reproduction.
- **No unified generic "block changes over time" hook exists.** Independent writers: `ChangeOverTimeBlock` copper weathering; `LeavesBlock.updateShape` → scheduled distance propagation and `randomTick` decay; `FarmBlock` moisture; `StemBlock` growing and fruit writer; `BigDripleafBlock` tilt scheduled; `FlowingFluid` fluid simulation; `BlockEntityTicker` and mods; weather precipitation; redstone neighbor state; items (wax/axe/bonemeal/lightning). Keep each owner distinct while sharing safe event provenance.
- **Fluid platform extension:** later official NeoForge `LiquidBlock` patch replaces `shouldSpreadLiquid` usage in `onPlace` and `neighborChanged` with `FluidInteractionRegistry.canInteract`. Preserve current target NeoForge fluid interaction hooks at placement/neighbor boundaries even if a future local-gravity fluid propagation adapter changes the direction algorithm. Do not infer exact hook existence from a newer source patch; add exact target test only after confirmed symbol and descriptor.
- BE ticking, redstone and biome-driven mutations need their own version/persistence/event/invalidation gates: no blanket `BlockState` time field, no mod-copying assumptions. Java mods can write arbitrary state via Level/BE without inheriting vanilla ChangeOverTimeBlock.

## 3/4 — deepest safe reusable boundary and mod compatibility

**Central rule:** `TIME DRIVER` ≠ `TEMPORAL ALGORITHM` ≠ `STATE WRITER` ≠ `SPATIAL COORDINATE DOMAIN`.

| Call family | Disposition | Safe treatment |
| --- | --- | --- |
| `LevelTicks` queue, block/Fluid identity, ScheduledTick, priority, subTick, tick time and chunk boundaries | **PHYSICAL_DO_NOT_TOUCH** for default semantics | Preserve vanilla bounded queues/persistence and real physical keys; Planet virtual chart can be opt-in through explicit own queue |
| `ServerLevel.tickChunk` random sampling / game rule | **SHARED_SAFE observation** | Use identical loaded-section sampling semantics; typed Planet chunk owner must account for virtual data independently, not globally mutate chunk random algorithm |
| `BlockStateBase.tick/randomTick`, `FluidState.tick/randomTick` virtual call | **SHARED_SAFE polymorphic dispatch** | Pass real current mod/vanilla BlockState, correct physical/canonical target and clock source without modifying override |
| `FlowingFluid`, support/growth neighborhood, leaf-distance, copper `withinManhattan` | **OPT_IN_ALGORITHM** | Explicit source+target frame and proper graph/metric chosen by algorithm; never globally rotate physical BlockPos/Direction/FluidState |
| BlockEntity/server event, structure/command, foreign Level and independent mod time-writers | **MOD_INDEPENDENT/PHYSICAL** | Opt-in extension or dedicated observed owner hook, preserve actual BE NBT and capabilities |
| Client `animateTick`/particles | **CLIENT RENDER** | Not authoritative mutation; separate game/render phase |

Real pinned NeoForge 1.21.1 third-party mod owner examples already researched in [Stage3A temporal atlas](PHASE2_STAGE3A_TEMPORAL_MUTATION_MECHANISM_MOD_SOURCE_ATLAS_1_21_1.md): `Caverns & Chasms` has independent weathering block algorithm (repository commit `d5600c66ff304aeea9d7c8064d80931e2df22733`, builds 21.1.222 not target 21.1.215); `Farmer's Delight` has separate crop/soil and cooking-pot BE ticking; a vanilla ChangeOverTimeBlock Mixin cannot cover an independently implemented method. Binary load on target version is NOT tested. **One level deeper**, globally changing `LevelTicks.tick`/physical chunk/block position/Direction/flow changes any third-party physical simulation. **One level shallower**, only patching copper/leaves/saplings misses independent mod growth and fluids. Proposed future stable Planet `TemporalTickProvenance` value (NOT implemented) must tag SCHEDULED_BLOCK/SCHEDULED_FLUID/RANDOM_BLOCK/RANDOM_FLUID/BE/EVENT, game time, actual State/Fluid owner, original/target physical pos, optional canonical chart/frame, chunk loaded and source author.
