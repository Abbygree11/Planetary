## 1/4 — Original dynamic shape virtual receiver, reproducible test

Previous `3R-2i` proved from *actual target original classfiles* that `BlockStateBase` declares `getCollisionShape` (getter/position with and without CollisionContext), `getOcclusionShape`, `getFaceOcclusionShape`, `getBlockSupportShape`; that the three `SupportType` concrete implementations query support shapes with distinct FULL/CENTER/RIGID masks; and that NeoForge `IBlockStateExtension` dynamically calls concrete `Block.hidesNeighborFace` / `supportsExternalFaceHiding` methods. Those proofs are compiled callsite/declared-owner evidence, not dynamic subtype runtime evidence.

Committed **[`Phase3R2jDynamicShapeAndForeignGetterDispatchTest`](../../src/test/java/dev/planetary/world/Phase3R2jDynamicShapeAndForeignGetterDispatchTest.java)** to execute the *real NeoForge 21.1.215 BlockState virtual entrypoints* against a synthetic `Block` subclass with `Properties.of().dynamicShape()`. This deliberately **does not create a Minecraft Planet world, add a runtime patch, install Create/AE2, or apply Mixins**. The block has actual Java overrides of `getCollisionShape`, `getOcclusionShape`, `getBlockSupportShape`, `hidesNeighborFace` and `supportsExternalFaceHiding`, with counters to expose actual effective receiver invocation rather than inspect an `INVOKEVIRTUAL` operand alone.

Two deliberately unrelated getter identities of `BlockGetter` (neither is a `Level`), two BlockPos with different X parity, and a mutable getter `AtomicBoolean` control the shape and hook returns while the **BlockState object is held identical**. Five samples separately exercise same-State/different-position, same-State/different-getter, and same-State/getter/position after context changes and resets. Assertion paths pass via `BlockState.getCollisionShape(getter,pos)`, `getOcclusionShape`, `getBlockSupportShape`, `getFaceOcclusionShape` and `IBlockStateExtension` methods. The test exports `phase3-r2j-synthetic-dynamic-context-dispatch.tsv` and `...-summary.txt` into standard research artifact path.

**Evidence levels must not be conflated:** the synthetic Block proves JVM delegation *possible on this target engine* when its CI passes; it is not a proof that vanilla every dynamic block, AE2 `FacadeBlockAccess`, Create `ContraptionWorld`, or actual `BlockEntity` uses these data, or that a specific Minecraft player reproduced a visual bug. The mutable flag is an analogue for context mutation, **not** an actual block entity or world time integration.

## 2/4 — Collision/occlusion cache and world/position invalidation contract

Full original original vanilla census from `3R-2e`: **26,684** registered BlockState values, **26,505** cached, **179** uncached, **22** dynamic-flag block IDs. This constrains only *registered vanilla* states; it does not exhaust modded state subclasses. Original `BlockStateBase.Cache` uses a canonical constructor context to cache eligible static shapes and support. A dynamic model must not be reduced to the same `(BlockState,BlockState,direction,direction)` key unless its true effective geometry and face visibility are independent of query getter, position, BlockEntity/time, config, model data and world identity.

Planet source [`PlanetBlockRenderCulling`](../../src/main/java/dev/planetary/client/render/PlanetBlockRenderCulling.java) currently calls original `skipRendering` and `hidesNeighborFace / supportsExternalFaceHiding` *before* caching. For occluding-state pairs it constructs the exact key
`CacheKey(state,neighborState,sourceLocalSide,targetLocalSide)` and caches Boolean face result; the actual source/neighbor `getFaceOcclusionShape(level,pos,localSide)` calls occur **after** cache miss. The world/getter identity, source/neighbor position, dynamic state flag, BlockEntity, time/revision and invalidation epoch are not stored in that key, nor is the map invalidated merely by a neighbor change. Its 2048-entry ThreadLocal LRU bounds memory but not value staleness. This is a **source-verified general counterexample risk**, pending actual loaded mod/world demonstration.

When the same state and local direction returns different shapes per context, an unchanged key may return the previous visibility result without invoking the real mod's context-sensitive geometry. Eligibility classification is more important than globally adding expensive cache-key material; correct eventual solution may be a fast static-only path with guarded dynamic uncached path plus explicit lifecycle invalidation. This is an **unimplemented research proposal**, not approval of a runtime fix.

## 3/4 — Real source-of-world provenance, Create/AE2 bypasses and frame precedence

Three independent current Planet sources establish distinct boundaries:

- [`PlanetBlockShapeRuntime.finishPhysical`](../../src/main/java/dev/planetary/world/PlanetBlockShapeRuntime.java): rotates a physical VoxelShape only at outermost query when the given BlockGetter `instanceof Level` and `PlanetBlockRuntime.stateFrameAt(level,pos)` is present; for other getters, returns the same canonical shape. The ThreadLocal depth specifically prevents nested double-rotation.
- [`PlanetClientRenderFrame.stateFrameAt / candidateFacesAt`](../../src/main/java/dev/planetary/client/render/PlanetClientRenderFrame.java): if getter `instanceof Level`, use that Level directly; otherwise fallback to `Minecraft.getInstance().level` at **the same supplied BlockPos**. There is no verification that arbitrary fake-world getter positions refer to that ClientLevel.
- [`PlanetBlockRenderCulling`](../../src/main/java/dev/planetary/client/render/PlanetBlockRenderCulling.java): uses the `BlockGetter` to read neighbor state but may infer both local-frame sides from an *independent active ClientLevel* when getter isn't a Level. That can mix one world's stored block data with another world's gravity/face-frame provenance.

The above mismatch is **proved at source level** even without a particular mod being loaded. The answer must be based on a producer-authored provenance relation; Java class/`instanceof Level` alone is not sufficient for virtual worlds. Previously verified release-equivalent 1.21.1 source and JAR ABIs: Create6.0.10 `ContraptionWorld extends WrappedLevel` and owns contraption-space state, `VirtualRenderWorld extends Level` but owns separate render blocks/chunks/light; Ponder1.0.82 `WrappedLevel extends Level` and delegates; AE2 19.2.18 `FacadeBlockAccess implements BlockAndTintGetter`, substitutes facade state and is not a Level; `GlassBakedModel`/`CableBusBakedModel` generate model/ModelData/quad paths independently. These bypasses must remain explicit source-only / released ABI—not a claim of running mods in Planet.

**Proposed provenance decision matrix (not implemented):** actual bound physical Level+pos ⇒ use Planet field; transparent wrapper ⇒ inherit only where exact position translation and delegation have been proven; independent virtual Level ⇒ own frame or no Planet; non-Level region/`BlockAndTintGetter` ⇒ use source-authorized producer world+coordinate transform, otherwise no guessed active-world binding; no Planet / other dimension ⇒ unchanged vanilla geometry and culling. Preserve both source and neighbor local sides across all 12 chart seams, including 8 corner cases. A global rewrite of `BlockGetter`/`Direction` or naive cached shape rotation is not equivalent.
