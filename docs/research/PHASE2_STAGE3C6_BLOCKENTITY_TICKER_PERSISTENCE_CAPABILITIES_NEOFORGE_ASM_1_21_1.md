## 1/4 — full dispatch owner and exact lifecycle split

| Real owner | Callback/writer | Crucial semantic rule |
| --- | --- | --- |
| `BlockStateBase.getTicker(Level,BlockEntityType)` | Virtual `EntityBlock.getTicker(level,state,type)` or null | Actual block and BE type determine **server/client separate** ticker implementation; mods override independently |
| `LevelChunk.updateBlockEntityTicker(BlockEntity)` | Dynamically requests current state ticker; either unregisters or installs/rebinds | **This**, not `Level.setBlockEntity` alone, registers a periodic callback; reevaluate on state change/replacement |
| `LevelChunk$RebindableTickingBlockEntityWrapper` | Stable ticker wrapper in Level list while concrete ticker can change | Prevent stale callback when state/type switches; `removeBlockEntityTicker` detaches |
| `LevelChunk$BoundTickingBlockEntity.tick` | Checks not removed, has Level, chunk is ticking, actual current state valid for BE type, then `BlockEntityTicker.tick(level,pos,state,be)`; reports invalid/crashing BE | *Do not* blindly tick every object in PlanetBlockEntityStore; preserve loaded chunk and type validation |
| `Level.tickBlockEntities` | Pending ticker queue, shouldTickBlocksAt, tickRateManager, removal cleanup; NeoForge fresh BE `onLoad` callback | **Independent clock** from `LevelTicks` and `ServerLevel.tickChunk` random ticks. Client and server logic may differ |
| `BlockEntity` + `LevelChunk` | `setRemoved/clearRemoved`, `isValidBlockState`, `setBlockState`, `loadWithComponents/saveWithFullMetadata`, `getBlockEntityNbtForSaving` | Preserve NBT custom fields/attachments/BE type and data components; update tag and packet are separate **client sync** path |
| `ServerLevel` NeoForge | `invalidateCapabilities(BlockPos)`, `registerCapabilityListener(BlockPos,listener)` | Capabilities and attached mod listeners keyed by *actual* position; remapping must keep identity, avoid double notifications |
| `LevelChunk.clearAllBlockEntities` | `onChunkUnloaded`, remove tickers, mark removed, invalidate capabilities | Chunk unload must terminate tickers and preserve serialized state, not lose data |
| `AbstractFurnaceBlockEntity.serverTick`, `TrialSpawnerBlockEntity`, `VaultBlockEntity`, mod BE | Independent BE business logic/serialized timers | Not derivable from `BlockState.randomTick`; no generic assumption all BEs tick |

**Key dispatch:** State owner supplies BE ticker, `LevelChunk` registers wrapper in `Level`, `Level.tickBlockEntities` invokes wrapper, wrapper verifies live BE/type/chunk, then polymorphically calls mod/vanilla `BlockEntityTicker.tick`. BE persistence/wiring, sync and capabilities are **parallel** ownership paths.

## 2/4 — Planetary actual implementation, gaps and regressions to avoid

Directly reviewed project:
- [PlanetBlockEntityStore](../../src/main/java/dev/planetary/world/PlanetBlockEntityStore.java) holds a `Map<PlanetBlockPos, BlockEntity>`, creates via `EntityBlock.newBlockEntity`, validates `isValidBlockState`, retains old compatible instance or removes and recreates, applies `setRemoved` to replaced/removed instances, and encodes face position to `PlanetVanillaPosCodec`. This stores **real** mod BE objects, which is good. It does **not** itself install `BlockEntityTicker`, call `onLoad`, or serialize a chunk.
- [PlanetWorldAccess](../../src/main/java/dev/planetary/world/PlanetWorldAccess.java) `bindLevel` sets BE Level for existing objects; `setBlock` runs `oldState.onRemove` then `newState.onPlace`, checks actual stored state, calls `blockEntities.reconcileBlockState`, dispatches neighbor updates; `setBlockState` also reconciles. It does **not** contain an independent `runBlockEntityTicks` registry/driver or a demonstrated LevelChunk wrapper registration for **virtual-store-only** BEs. A foreign/physical LevelChunk instance can tick its own BEs, but a Planet-only object may never be registered into it. **Possible implementation gap** (source-level, game not reproduced): a virtual furnace/trial spawner/third-party processing machine could exist and persist in memory yet never receive periodic `serverTick`.
- [LevelMixin](../../src/main/java/dev/planetary/mixin/LevelMixin.java) routes `Level.getBlockEntity`, `setBlockEntity`, `removeBlockEntity` via Planet bridge; `setBlockEntity` calls BE.setLevel, inserts straight into Planet BE map and cancels HEAD. **This bypasses LevelChunk.addAndRegisterBlockEntity + updateBlockEntityTicker and NeoForge fresh-BE onLoad queue on the intercepted path.** Direct call owner contract can be verified without asserting actual live failure. `removeBlockEntity` removes map (and calls setRemoved) but does not directly install/uninstall a LevelChunk wrapper; if alternate registration exists, must trace.
- [ServerLevelMixin](../../src/main/java/dev/planetary/mixin/ServerLevelMixin.java) `invalidateCapabilities` and `registerCapabilityListener` remap positions through `PlanetSidedQueryFrame.canonicalize` with a re-entry call and cancel. Check listener identity and cache invalidation in a real NeoForge mod consumer, on both source and target charts: avoid mixing virtual encoded and actual physical keys. No BE ticker Mixin is installed in this package.
- [PlanetBlockEntityStoreTest](../../src/test/java/dev/planetary/world/PlanetBlockEntityStoreTest.java), [PlanetBlockEntityLevelBindingTest](../../src/test/java/dev/planetary/world/PlanetBlockEntityLevelBindingTest.java), [PlanetWorldBlockEntityTest](../../src/test/java/dev/planetary/world/PlanetWorldBlockEntityTest.java) are local state/lifecycle tests, **not** actual live LevelChunk ticker/saved-chunk/mod capability acceptance. No complete persistent save/load encoding path for the virtual BE map is present in reviewed current `PlanetBlockEntityStore` or `PlanetWorldAccess`; **potential persistence gap**, not proof worlds lose data at restart until runtime/path analysis across project storage.
- Existing `LevelMixin` `getBlockEntity` may return an object with a virtual VanillaBlockPos, which is necessary for chart mapping; blocks/mod capability systems expecting a real physical location must be given type-safe provenance, not blindly rewritten global positions.
- NeoForge `BlockEntity` `clearRemoved` and `setRemoved` can invalidate capabilities, plus `onLoad`, chunk unload, supplemental NeoForge attachment NBT/model data callbacks. Blind removal/creation can cause lost inventories, attachments, client render data, capabilities and mod listeners; exact target version is separately pinned by ASM. *Do not* assume `onChunkUnloaded` is identical to `setRemoved`, nor that a mod state replacement should preserve incompatible BE contents.

## 3/4 — deepest safe boundary / generic mod compatibility

| Hook/contract | Disposition | Reason |
| --- | --- | --- |
| `LevelChunk` real chunk BE ticker map, `BlockEntityType`, `Level.tickBlockEntities` defaults, physical `BlockPos` and loaded status | **PHYSICAL_DO_NOT_TOUCH** | Real vanilla/NeoForge mods must keep physical chunks, temporal ordering and keys |
| Dynamic `BlockStateBase.getTicker` → `EntityBlock.getTicker`, `BlockEntityTicker.tick` | **SHARED_SAFE dispatch/observation** | Common *interface* accommodates third-party mod BE ticker implementations without named-block patches |
| Planet-owned virtual BE lifecycle/provenance (real state/type, chart coordinate, encoded world position, real Level, loaded/tickable status, onLoad/removal bookkeeping) | **SHARED_SAFE new ownership design** | Register/rebind/unregister in a **Planet-owned** ticker controller, feeding real polymorphic BE callback without modifying global chunk scheduler |
| Per-block machine behavior, inventories/tanks, BE NBT/attachments, comparator output, external capabilities | **MOD_INDEPENDENT** | Preserve normal vanilla/NeoForge callback and serialization paths; do not copy vanilla furnace logic |
| Local-gravity sided machine fronts, hopper/cable faces, chart seam routing | **OPT_IN_ALGORITHM** | World-side capacity/ports are physical by default, local semantic owner can supply transported canonical directions |
| Client BER, update packet/tag, model data and animation | **CLIENT RENDER/SYNC** | Not equivalent to server BE tick or persistence; independent client acceptance |

**One level deeper (unsafe):** globally converting `LevelChunk` coordinates/ticker table, `BlockEntity.getBlockPos`, `ServerLevel.invalidateCapabilities`, or `Level.tickBlockEntities` would break physical mods, fake levels and real chunk persistence. **One level shallower (insufficient):** patching furnace/spawner/trial spawner individually misses every modded `EntityBlock.getTicker`, stored object reconciliation, NeoForge callbacks and BE types. Proposed stable typed `PlanetBlockEntityLifecycleContext` with real Level and BE, canonical `PlanetBlockPos`, encoded virtual pos, current BlockState, type, source chart, loaded state, stage `CREATE/LOAD/START_TICK/REPLACE/UNLOAD/SAVE`; a thin Minecraft21.1.1 adapter owns `getTicker`/NBT/NeoForge hooks. **Only design, not implemented in this stage**.

Pinned third-party source comparator: [Farmer's Delight temporal/growth/ecology/BE audit](PHASE2_STAGE3A_TEMPORAL_GROWTH_ECOLOGY_BE_MOD_OWNER_AUDIT_1_21_1.md) shows independently serialized/ticked cooking-pot BE; [AE2 and mod machine compatibility research](PHASE2_STAGE3A_MODDED_CRYSTAL_AE2_BUDDINGCRYSTALS_1_21_1.md) demonstrates non-vanilla block state/BE-driven algorithms. They are source-level owner examples **without** a loaded target21.1.215 mod JAR acceptance claim.
