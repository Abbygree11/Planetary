## 1. The user constraint: deepest SAFE algorithm/engine seam, no block-specific patch-by-default

**Deepest != broadest Mixin injection.** The deepest shared *semantic* boundary must retain physical coordinates, third-party providers' physical sided contexts, original registry dispatch, worldgen/fake Levels, target BlockStates and independent algorithm semantics. The design should support vanilla + mods without a list of hardcoded block IDs, yet may need an opt-in policy per algorithm/family; blanket `Direction.UP/DOWN`, `BlockPos.relative`, `getHeight`, `FluidState`, `Level.getBlockState/setBlock`, `NeighborUpdater` rewrites would change independent modded physical simulations and are **FORBIDDEN without exhaustive provenance proof**.

**Mandatory every future research packet** (and any actual Java implementation after separate authorization):
1. **Exact dispatch and source provenance:** all registered vanilla class IDs and original full-qualified effective declaring owners; source/base class/sibling override path, enum/property legality and late ItemStack components; original NeoForge patched ASM targets and access restrictions **separate runtime gate**. Trace calls through `BlockItem / BlockStateBase / NeighborUpdater / LevelAccessor / Feature / BlockEntity / Entity` as applicable, and **all alternate writers** (worldgen, custom Items, bonemeal, commands, structure, tick, fluid). Correct overloaded method resolution requires FULL parameter types, not first method of same name.
2. **Domain intent per operation, not per class:** identify PHYSICAL (true XYZ neighbor/graph), CANONICAL local source+target state (wall/ground/support face), TRAVERSAL chart (edge/corner step with transported tangents), WORLDGEN volume/heightmap (biome+source algorithm), FOREIGN/virtual Level (contraption/clipboard), CLIENT RENDER (VoxelShape/particle). One class may use multiple domains simultaneously; e.g. amethyst grows across true six physical neighbors but its item-placed crystal can have local semantic supporting face on planetary sides.
3. **Deepest candidate and override-safe boundary:** classify `BlockStateBase`/placement/neighbor callbacks, `PipeBlock` shapes, generic support, BlockItem, feature coordinates, graph topology vs own algorithm decisions; propose stable Planet-owned pure helper / typed API FIRST, then thin vanilla/NeoForge version adapters, then opt-in algorithm-family or mod-provided hooks. If source code has a true independent override or a mod reimplements semantics independently, **do not claim** vanilla inherited-Mixin coverage. Provide a reason why moving the adapter one level deeper would be unsafe, and why choosing one level shallower would under-cover modded siblings.
4. **Modded evidence:** search relevant actual public **1.21.1** mod source(s) for both inheritance and copy/reimplementation, pinned SHA/MC/NeoForge version; if no verified analog found, record no evidence rather than invent. Distinguish same `BlockStateProperties.FACING` from same Java method owner, and inherited code from override. Plan optional registration/semantic adapter policy; default unknown mod to physical semantics and no altered world graph.
5. **Independent acceptance and regression gate:** normal non-Planet world, six Planet canonical face interiors, 12 face-pair edges, 8 triple corners, XZ-chunk/restart, source and target real BlockPos, actual modded runtime class/method owner, transformed ASM proof, adapter runtime dispatch, gameplay outcome, worldgen/fake Level and fluid/shape as applicable. ALL such future fixtures are `NOT RUN` until independently executed. Do not promote any of vanilla 241×3 patched-bytecode/Planet/gameplay status based only on source. Separate modded census; do NOT inflate vanilla original BLOCK IDs.

## 3. Stage3A-16 actual example proves the need for explicit domains

- `ChorusPlantBlock extends PipeBlock` reuses 64 cached 3D physical arm shapes and a `Direction→BooleanProperty` map, but **overrides** getStateForPlacement, canSurvive, updateShape itself. A patch confined to `PipeBlock` shape does not cover the other three calls. An engine-wide `NeighborUpdater` direction mutation would silently corrupt any modded pipe/block which expects physical network sides. Safe generic helper: **one physical callback plus explicit source+target canonical frames and semantic policy**, no auto rewrite by FACING-like property.
- `ChorusFlowerBlock` branches/grows in **world-UP and world HORIZONTAL XZ**, checks local column heights and source `END_STONE` plus one horizontal support and occupancy. `ChorusPlantFeature` directly invokes recursively generated plants, bypassing item-placement; source `ChorusPlantBlock` six physical boolean graph is separate. A Planet-specific **surface-growth algorithm policy** with a *worldgen or runtime origin* may transport up/tangent local intention to real positions; **physical neighbor graph is separately preserved** and never generally rotated.
- `BuddingAmethystBlock` grows among actual six physical neighbor cells; AE2 `BuddingCertusQuartzBlock` copies it without shared inheritance and independently implements placement/survival. BuddingCrystals subclasses `BuddingAmethystBlock` but overrides randomTick while creating actual vanilla `AmethystClusterBlock`. This makes blanket vanilla-Mixin compatibility false; adapters should target shared *semantics* only where provenance exists and optional mod-provided bridge fills demonstrable gaps.
