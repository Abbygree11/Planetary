## 2/4 — Released Create 6.0.10 instance geometry, visual transformations and foreign levels

**Release pin:** [Create `mc1.21.1-6.0.10` at `ac0c444d9828da3453ae8cc65338e8de063286fb`](https://github.com/Creators-of-Create/Create/tree/ac0c444d9828da3453ae8cc65338e8de063286fb); immutable release source `gradle.properties` selects **MC 1.21.1, NeoForge 21.1.219, Flywheel 1.0.6, Ponder 1.0.82**. This is a **source pin, not original Flywheel library 1.0.6 binary API**. Earlier [`3R-2h` compiled release binary audit](PHASE3_R2H_RELEASE_BINARY_ABI_AND_ENGINE_CALLPATH_DISPOSITION_1_21_1.md) additionally verified selected Create 6.0.10, Ponder1.0.82 and AE2 19.2.18 method owners, not Flywheel GPU draw internals or any loaded mod.

- [`AllBlockEntityTypes`](https://github.com/Creators-of-Create/Create/blob/ac0c444d9828da3453ae8cc65338e8de063286fb/src/main/java/com/simibubi/create/AllBlockEntityTypes.java) has 104 **textual** `.renderer(` and 69 **textual** `.visual(` Registrate declarations (not actual loaded renderer counts), as established by [3R-4D](PHASE3_R4D_NEOFORGE_BER_PROVIDER_REGISTRATION_MOD_OWNER_1_21_1.md).
- [`KineticBlockEntityRenderer.renderSafe`](https://github.com/Creators-of-Create/Create/blob/ac0c444d9828da3453ae8cc65338e8de063286fb/src/main/java/com/simibubi/create/content/kinetics/base/KineticBlockEntityRenderer.java) calls `VisualizationManager.supportsVisualization(be.getLevel())` then **returns** when Flywheel visualization is supported; otherwise uses `CachedBuffers.block`, `SuperByteBuffer` and `renderRotatingBuffer`. This is a **bypass/switch** between rendering pathways, not a proof both are correctly rotated in Planet.
- [`SingleAxisRotatingVisual`](https://github.com/Creators-of-Create/Create/blob/ac0c444d9828da3453ae8cc65338e8de063286fb/src/main/java/com/simibubi/create/content/kinetics/base/SingleAxisRotatingVisual.java) extends `KineticBlockEntityVisual` and calls `instancerProvider().instancer(AllInstanceTypes.ROTATING, model).createInstance().rotateToFace(...).setPosition(getVisualPosition())`; `update`, `updateLight`, `_delete` update/relight/delete the instance. [`OrientedRotatingVisual`](https://github.com/Creators-of-Create/Create/blob/ac0c444d9828da3453ae8cc65338e8de063286fb/src/main/java/com/simibubi/create/content/kinetics/base/OrientedRotatingVisual.java) similarly rotates source `from` to state-derived `to`. A normal vanilla BER HEAD/RETURN Mixin does not wrap these GPU instances.
- [`FlywheelVisual`](https://github.com/Creators-of-Create/Create/blob/ac0c444d9828da3453ae8cc65338e8de063286fb/src/main/java/com/simibubi/create/content/kinetics/flywheel/FlywheelVisual.java) has two different instances: `ROTATING` shaft and `TRANSFORMED` wheel, copies `wheel.pose` to `Matrix4f baseTransform`, updates frame animation via `beginFrame`, and independently `relight` / `delete`. The visual's model transform, animation and light updates have independent owners. Raw `Matrix4f` does not by itself guarantee world-correct GPU normal/PBR orientation.
- [`ContraptionVisual`](https://github.com/Creators-of-Create/Create/blob/ac0c444d9828da3453ae8cc65338e8de063286fb/src/main/java/com/simibubi/create/content/contraptions/render/ContraptionVisual.java) extends `AbstractEntityVisual` and implements `DynamicVisual`, `TickableVisual`, `ShaderLightVisual`. It uses `VisualEmbedding` / a `contraptionMatrix`, a `VirtualRenderWorld`, `WrappedBlockAndTintGetter`, `BlockModelBuilder`, `InstanceTypes.TRANSFORMED`, `VisualizerRegistry.getVisualizer` for child BEs and separate actor visuals. Its nested renderer belongs to moving **entity/contraption-local** frame, possibly with **independent light sample world**. Rotating the same geometry again at a global BER or physical BlockPos seam is unsafe; implementation scope must distinguish each child and parent.
- [`ActorVisual`](https://github.com/Creators-of-Create/Create/blob/ac0c444d9828da3453ae8cc65338e8de063286fb/src/main/java/com/simibubi/create/content/contraptions/render/ActorVisual.java) samples brightness from `simulationWorld` at `context.localPos` and owns `delete`/update separately. This is another non-vanilla rendering ownership route.

**Flywheel release artifact provenance:** the actual official Create Maven [flywheel-neoforge-1.21.1/1.0.6 index](https://maven.createmod.net/dev/engine-room/flywheel/flywheel-neoforge-1.21.1/1.0.6/) lists the **compiled 853 KB JAR**, **430 KB source JAR**, associated Javadoc and `.sha256` files (published 2026-01-02), rather than just a guessed library version. Direct browser file retrieval rejected binary/application-java-archive and container download failed; therefore **Flywheel 1.0.6 bytes, SHA and javap are NOT independently verified in this packet**. Pin exact official paths for later downloader with network access; never invent a checked digest or assert GPU shader classfile ABI without receiving those bytes.

**Compatibility limitation:** Create release source targets NeoForge **21.1.219** rather than current Planet **21.1.215**; not evidence of loading/failure in Planet. Flywheel **1.0.6** external backend classfiles and supported renderer/instancing shaders not downloaded or target-bytecode verified. Thus exact lower-level GPU implementation, model normal computation, backend selection and mod client acceptance **remain open**. Do not claim support from the Create source API alone.
