## Принцип механизма

Нельзя исправлять ориентацию на уровне одного видимого `EnderChestBlock`/свечи и объявлять семейство готовым. Нужно определить **всех владельцев алгоритма**: базовый класс, overrides, созданные/заменённые состояния после установки, item/dispenser/worldgen, физический target и локальную семантику, canSurvive/updateShape/neighborChanged, рендер/BE и NeoForge-модификации. Один механизм может иметь несколько тонких точек интеграции, но одну стабильную Planet-семантику.

Решение: физический dispatch с typed provenance без глобального переписывания `Direction`/`BlockPos.relative`; отдельная Planet-owned shared semantic engine helper source+target frame и opt-in per algorithm, для неизвестных модов по умолчанию физическая семантика; optional mod adapters только после независимого runtime-доказательства gap. Доказать, почему ещё глубже небезопасно и мельче не покрывает sibling/mod override. Тесты реальные модовые/ASM/Planet/client/server строго отдельно.
