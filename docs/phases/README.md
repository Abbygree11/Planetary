# Planetary — поэтапная работа с короткими checkpoint-файлами

Рабочая ветка: **2.0** (никогда `main`). Minecraft 1.21.1, NeoForge 21.1.215, Java 21.

## Зачем существует эта папка

Большие одновременные исследования и ответы неоднократно обрывались. Теперь **каждая фаза разбита на небольшие законченные пакеты**, результаты которых сохраняются в GitHub **до** перехода к следующему пакету. Один пакет — один самостоятельный результат (исследование, матрица покрытия, механизм, тест/CI либо приёмка). Не пытаться завершить все пакеты за один ответ.

Источники истины: [AGENTS.md](../../AGENTS.md) — процесс; [IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md) — утверждённый глобальный роадмап; [AI_CONTEXT.md](../AI_CONTEXT.md) — история; [research](../research) — доказательства. Эти файлы — **пошаговые рабочие карточки**, не замена источникам истины.

## Общий порядок для каждого пакета

1. Прочитать `AGENTS.md`, текущую фазу и соответствующие исследования; проверить HEAD ветки `2.0`.
2. Выбрать **один** первый незавершённый пакет, точно определить границы, зависимости и ожидаемый выходной артефакт.
3. Исследовать реальные механизмы, включая наследование, альтернативные пути и NeoForge-патчи. Не править один блок без исследования его семейства.
4. Сохранить законченный результат прямо в `2.0`: дополнить артефакт, отметить `DONE` только по подтверждённым критериям, записать следующий пакет.
5. Если затронут код — добиться зелёного `compileJava + compileTestJava + test` в GitHub Actions **после последнего изменения кода**. Если только документация — не требовать лишней пересборки.
6. Игровой `PASS` фиксировать **только** после подтверждённой проверки поведения, отличать от `IMPLEMENTED / CI PASS / GAMEPLAY PENDING`.
7. Закончить ответ **на границе пакета**. Следующий ответ продолжит следующий пакет. Не делать длинный непрерывный цикл.

## Статусы

`TODO` — не исследовано/не сделано; `RESEARCHED` — механизм подтверждён исходниками, не исправлен; `IMPLEMENTED` — код есть, интеграция не принята; `CI PASS` — компиляция/тесты успешны; `GAMEPLAY PASS` — игровая приёмка подтверждена; `BLOCKED` — явная зависимость с владельцем; `DONE` — критерии данного маленького пакета выполнены, но не обязательно всей фазы.

Не переносить `RESEARCHED` в `DONE` только из-за списка классов. Псевдопокрытие на основании regexp/названий запрещено.

## Правило после потери соединения

Посмотреть последнюю отметку `DONE` **в GitHub**, продолжить первый `TODO`. Если кусок не был закоммичен, считать его незавершённым. Не обещать фоновой работы: каждый шаг выполняется в явном ответе и завершается самостоятельным коммитом.
