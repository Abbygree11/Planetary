# Planetary — рабочие карточки фаз

**Ветка:** `2.0`. **Среда:** Minecraft 1.21.1, NeoForge 21.1.215, Java 21. Проект экспериментальный; `RESEARCHED`, `CI PASS` и `GAMEPLAY PASS` означают разные уровни проверки.

## Для чего нужны карточки

Фазы разбиты на небольшие завершённые **пакеты общих механизмов**, чтобы после обрыва чата не терять выводы и не повторять уже выполненные исследования. Результаты каждого пакета сохраняются в GitHub до перехода к следующему. Один пакет `2.3C-N` включает **сразу все четыре внутренние проверки** для одного согласованного семейства: исходники и точный NeoForge ABI, полный lifecycle и обходные пути, модовые расширения/безопасные границы, строгие ASM/JUnit-контракты с CI.

Карточки — навигация, не самостоятельный источник текущих фактов. Сверять состояние следует с [AGENTS.md](../../AGENTS.md), [глобальным roadmap](../IMPLEMENTATION_PLAN.md), [AI_CONTEXT](../AI_CONTEXT.md) и [исследованиями](../research/).

## Как продолжать работу

1. Прочитать `AGENTS.md`, действующий roadmap и релевантные исследования, проверить HEAD `2.0`.
2. Выбрать следующий **полный owner-family пакет**, установить владельца механизма и его альтернативные вызовы, включая NeoForge и моды.
3. Разделить физические координаты, локальную семантику Planetary, переходы граней, worldgen/fake Levels и клиентский рендер.
4. Сохранить итоговое исследование и строгий тест в репозитории. Для любых изменений тестового или рабочего Java-кода получить подтверждённый результат GitHub Actions **после последнего изменения тестов**.
5. Отмечать отдельно source-research, выбранный ASM/JUnit, запуск Minecraft, игровой тест шести граней/12 рёбер/8 углов и реальный загруженный мод.
6. Закончить на границе пакета; следующий запрос «кк» — следующий пакет, а не повтор старого.

При документационных правках в `README` / карточках не заявлять о готовности функций, если подтверждены только исходники или ASM. Изменения `docs/**` сами по себе не требуют новой Java-сборки.

## Если чат или проверка оборвались

Взять последний сохранённый коммит/отчёт из `2.0`, проверить связанную GitHub Actions job, затем продолжить первый не завершённый пункт. `CI PASS` без успешно завершившегося прогона не записывать. Не обещать фоновой работы или автоматического продолжения без отдельного запроса пользователя.
